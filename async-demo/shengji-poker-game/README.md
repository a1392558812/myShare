# 技术文档

> 规则细节见同目录 `RULES.md`

## 1. 概览

4 人 2v2 的双升扑克，玩家坐 0 号位（「你」），其余三家 AI。一局流程：洗牌发牌 → 亮主/反主 → 庄家扣底 → 出牌 25 墩 → 抠底与升降级 → 轮庄开下一局，打到某队过 A 通关。

## 3. 分层与数据流

```
core/game.js（唯一状态源 state，普通对象，不参与响应式）
      │  applyXxx() 返回 { ok, reason }
      ▼
composables/useShengji.js ── sync() ──▶ ui（reactive 镜像，只读给界面用）
      │                                    │
      │ buildView()                        ▼
      └──────────────▶ draw/renderer.js 渲染  components/*.vue 模板绑定
```

- 状态机全部在 `core`，`applyPlay` / `applyBury` / `applyDeclare` 都是「校验 + 就地改 state + 返回结果」，没有抛异常，也不碰 DOM。
- `ui` 是**单向镜像**：任何动作后调 `sync()` 把 state 拍平成界面需要的样子（手牌排序、分数、庄家、是否该我出牌），界面永远不直接改 state。
- 这样做的好处：`core` 可以在 node 里跑几万局自动对局做回归，界面层改样式不影响规则。

## 4. 状态机

```
idle ──startRound──▶ declare ──finishDeclare──▶ bury ──applyBury──▶ play
                        │                                            │
                        └──(无人亮主：翻底定主)                        │ 每墩 4 手
                                                                     ▼
                                                    play ──resolveTrick──▶ play
                                                                     │ 手牌出完
                                                                     ▼
                                                          settle ──nextRound──▶ declare
                                                                     │ 打 A 保级成功
                                                                     ▼
                                                                   over
```

阶段判定只看 `state.phase`；`pump()` 是唯一的「下一步该谁动」调度器：

| phase     | 处理                                                            |
| --------- | --------------------------------------------------------------- |
| `declare` | 轮到我 → 亮按钮；轮到 AI → 620ms 后 `aiDeclare`                 |
| `bury`    | 我是庄家 → 提示选 8 张；AI 庄家 → 560ms 后 `aiBury`             |
| `play`    | 轮到我且未托管 → 等待操作；否则 700ms 后 `aiPlay` + `applyPlay` |

一墩打完后 `showTrick()` 保留 1.15 秒展示赢家与得分，再清空出牌区继续，避免「牌一闪就没了」。

## 5. 核心数据结构

```js
state = {
  seed,
  random, // 可复现随机源
  phase,
  roundIndex,
  teamLevels: [2, 2], // 双方级别（rank 值 2..14）
  dealer,
  level,
  trumpSuit, // 庄家座位 / 本局打几 / 主花色（-1 = 无主）
  rule, // 由 level + trumpSuit 派生的规则上下文
  hands: [[], [], [], []], // 每家手牌（25 张，庄家扣底前 33 张）
  kitty,
  buried, // 底牌 / 庄家扣下的牌
  declare: { stage, cursor, order, best, log },
  turn,
  leader,
  trickPlays, // 当前该谁出 / 本墩首家 / 本墩已出的手
  history,

  teamPoints: [0, 0], // 两队累计抓分

```

`rule` 是纯函数产出的上下文，包含 `tierOf / groupOf / isTrump / rankSequence / trumpLabel`。所有比较都走 `rule`，所以「主牌算一门」这件事只在一处定义。

## 6. tier：把主牌大小压成一维序号

主牌里混着大王、小王、主级牌、副级牌（三门等大）和主花色普通牌，直接比 `rank` 是排不出来的。这里给每张牌算一个整数 `tier`：

打 10、主红桃：

| tier  | 牌                              |
| ----- | ------------------------------- |
| 15    | 大王                            |
| 14    | 小王                            |
| 13    | 主级牌（红桃 10）               |
| 12    | 副级牌（黑/梅/方 10，彼此等大） |
| 11..0 | 红桃 A K Q J 9 8 7 6 5 4 3 2    |

好处有三个：

1. 比较大小只需 `tier` 比大小，`playPower` 再叠一层「主牌压副牌、不同副牌花色不互压」。
2. **连对判定直接变成「tier 相邻」**，不用为级牌/王特判，天生长出「副级对 + 主级对 + 王对」这类连对。
3. 甩牌拆组、跟牌挑对子、AI 排序全都复用同一套 `tier`。

无主时四门级牌同 tier（彼此等大、不能成对，因为成对看 `cardKey` 花色+点数），小王、大王各升一级。

## 7. 牌型识别与比较（meld.js）

`analyzePlay(cards, rule)` 返回 `{ cards, group, size, pairs, topTier, pairTiers, kind }`：

- `group`：全在同一门 → 该门（主牌是 `'T'`）；跨门 → `null`（跨门只可能是「垫牌」）。
- `pairs`：按 `cardKey` 分桶后每桶取 `floor(n/2)`，累加得到对子数。
- `kind`：`single` / `pair` / `tractor`（全是对子且 tier 连续）/ `mixed`（甩牌或垫牌）。

比较分两步：

```js
playPower(play, leadGroup); // 跨门垫牌 0 < 其他副牌花色 0 < 首家花色 1 < 主牌 2
beatsPlay(challenger, defender, leadGroup);
// 垫牌永远 false；对子数少于首家 false；power 不同比 power；相同比 topTier
```

`resolveWinnerIndex` 从首家开始逐手挑战当前最大，`group === null` 的手直接跳过——所以「三家全垫牌 → 首家赢」是自然结果。

## 8. 跟牌：校验与构造分离（follow.js）

**校验** `validateFollow(hand, lead, cards, rule)`，三种情况：

| 情况                              | 要求                                                 |
| --------------------------------- | ---------------------------------------------------- |
| 张数不对                          | 直接拒，提示「必须出 N 张」                          |
| 本门够 `mine.length >= lead.size` | 必须同门；对子数 ≥ `min(首家对子数, 手里本门对子数)` |
| 本门不够                          | 本门的牌必须全部打出，剩余张数用别门补，补牌可跨门   |

**构造** `buildFollow(hand, lead, rule, options)` 是校验的逆运算，给 AI 和「提示」按钮用：

- `composeFrom(pool, count, needPairs, rule, options)`：先从池子里挑 `needPairs` 个对子（`high` 决定挑大的还是小的），再补散牌。
- 本门不够时按优先级补：想毙牌且主牌够 → 用主牌毙（挑大的）→ 否则垫别门（`avoidPoints` 时先垫无分牌）。

校验与构造分离后，AI 不需要「生成合法牌」的知识，只要说清意图（要不要压、要不要保分），合法性由构造器兜住。

## 9. 甩牌判定（resolveThrow）

甩牌合法性不看「最大那组」，而是逐组检查：

1. 把这手牌拆成组件：每个对子一组、剩下的单张各一组，按 `tier` 升序。
2. 对每个组件，扫描另外三家的同门牌：单张看有没有更大的单张，对子看有没有更大的对子。
3. 任意一家能压任意一组 → 甩牌不成立，**只打出最小的一组**（`components[0]`），并回报 `reduced`。

界面用 `outcome.reduced` 提示「甩牌被压，只出了最小的 N 张」——按规则这是「罚」，不是「提示玩家重选」。

## 10. 抠底与结算

`resolveTrick` 在收墩时判断：`hands` 全空（最后一墩）且赢家不是庄家队 → 底牌分 × `2^(赢牌对子数+1)` 计入闲家。

| 最后一手 | 倍数 |
| -------- | ---- |
| 单张     | ×2   |
| 1 对     | ×4   |
| 2 连对   | ×8   |
| 3 连对   | ×16  |

`settleRound` 用 `upgradeSteps(gained)` 查表（表在 `game.js`，与 `RULES.md` 第 9 节一一对应）：0 分大光 +3、5~35 小光 +2、40~75 +1、80 起闲家上台并按下限再升级。过 A 判定：庄家队级别已经是 A 时，只要保级（闲家 < 80）即通关；跳级最多停在 A。

轮庄：庄家队升级 → 对家（`dealer + 2`）坐庄；闲家上台 → `dealer + 1` 坐庄。

## 11. AI（ai.js）

| 场景   | 策略                                                                                                                         |
| ------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 亮主   | `groupStrength = 该门张数 + 级牌×2 + 王×2 (+3 若已是主)`，门槛 7（首亮）/ 8（反主）                                          |
| 反无主 | 手里 ≥3 张王或 ≥10 张主才反，避免见到王对就乱反                                                                              |
| 扣底   | 权重 `主牌 +1000、分牌 ×20、tier`，扣最小的 8 张 → 基本不扣主牌和分牌                                                        |
| 首出   | 主牌 ≥9 张先清主（出最小主）；否则从最长副牌门出最小单张（该门 ≥4 张且最小是现成对子时改出对子）                             |
| 跟牌   | 队友已赢 → 垫无分小牌；否则尝试 `buildFollow({high:true, trump:true})`，能压且（台面 ≥5 分或自己是最后一手）才压，压不了就垫 |

「值不值得压」只看两件事：这墩有没有分、自己是不是最后一手。这样 AI 不会为一张 5 分把大王打出去，也不会在最后一手把有分的墩让掉。

## 12. 渲染层（draw/）

- 逻辑分辨率固定 `1160 × 760`（`constants.js` 的 `DESIGN`），canvas 按容器等比缩放并乘 `devicePixelRatio`，之后 `setTransform` 一次，绘制代码全部用逻辑坐标。
- 牌面 `cards-art.js` 离屏预渲染后缓存，每帧只 `drawImage`，不重复画字。
- 位置全部来自 `LAYOUT`：手牌行（`handY` 648、最多 46px 步进、选中抬高 22px）、四家出牌区（`playZones` 四个圆心点）、中央信息盘（`center` 半径 96）。
- **命中测试与绘制共用 `layoutHand()`**：`toLocal()` 把客户端坐标换算回逻辑坐标，再从右往左逐张做矩形判定（后画的在上层），选中态用 `LAYOUT.handRaise` 抬高命中区，所以点选和视觉完全对得上。

## 13. 桥接层节奏与托管（useShengji.js）

- `later(callback, delay)` 统一管理定时器（单定时器，切换动作时清掉旧的），`ui.fast` 开启时把等待压到 1/8（最低 30ms），方便调试与自动验收。
- AI 出牌被拒时有兜底：用 `buildFollow` 重新构造一手合法牌，避免规则边界情况把整局卡死。
- `hint()` 直接复用 `aiPlay(state, 0)` 的结果，把建议的牌设为选中态，玩家可再调整。

**托管**靠三个钩子实现，而不是另写一套自动流程——`pump()` 在每个阶段只问一句「这一步该谁动、托管是否开着」：

| 阶段               | 托管关闭                                 | 托管开启                                            |
| ------------------ | ---------------------------------------- | --------------------------------------------------- |
| 亮主 `pumpDeclare` | 座位 0 弹亮主/反主/过按钮，等玩家点      | 走 `runDeclareSeat(0)`，520ms 后按 `aiDeclare` 决策 |
| 扣底 `pumpBury`    | 庄家是玩家 → 提示选 8 张                 | 460ms 后 `aiBury` 自动扣                            |
| 出牌 `pumpPlay`    | 轮到我 → `ui.awaitingPlay = true` 等出牌 | 照常走 AI 那条分支                                  |
| 结算 `settle`      | 弹结算窗，等玩家点下一局                 | 1.9 秒后自动 `continueNextRound()`；通关则关掉托管  |

几个容易踩的点：

- **开启托管必须立刻接管**：清掉 `ui.declare` / `ui.awaitingPlay` / 选中牌再 `pump()`，否则正在等玩家的那一步会一直停在那里。若结算窗正开着，则 0.9 秒后自动开下一局。
- **收回托管要还权**：若此刻正轮到我出牌，直接把 `awaitingPlay` 置回 true；AI 的定时器回调里也加了 `if (seat === 0 && !ui.autoPlay) { pump(); return }`，避免「刚点收回，AI 还是替我出了一手」。
- **`continueNextRound` 用 `ui.result` 兜底**：自动续局是延迟调用的，手动点下一局可能已经先跑了；没有结算窗就直接 return，避免把新一局又顶掉一局。
- 托管中屏蔽玩家操作（选牌、扣底、出牌、提示都 early return），按钮也让位给「收回托管」，不会出现人机同时动手。

## 14. 调试面板：牌局改造（core/debug.js）

调试面板可以做三件事：**看牌**（四家手牌 + 底牌全部亮出）、**换牌**（点一张 → 再点另一家的任意一张，两张对调）、**安排下次进张**（指定某家下一局起手必进哪些牌）。

### 14.1 完整性铁律

牌堆永远只能是「两副牌」：108 张、54 种牌各 2 张、id 不重复。所有调试动作都围绕这一条设计：

- **换牌是 1:1 位置置换**：两张牌只对调位置，多重集天然不变，四家手牌张数也不变，所以永远造不出「三张红桃A」或缺张。
- **安排进张是从真牌堆里挑牌**：`riggedDeal` 先把指定牌从洗好的 108 张里 `splice` 出来发给某家，剩下的牌照常扣底、轮流补齐——安排得再多也只是 108 张的一个排列。每种牌只挑得到 2 张（挑第 3 张时牌堆里已经没有），单家最多挑 25 张，超出部分自动作废。
- **每次操作后跑 `auditDeck`**：清点全区域（四家手牌 + 底牌 + 已打出的墩），检查总数 108、每种牌 2 张、id 无重复。不通过就**回滚本次操作**并提示。埋底阶段底牌已并入庄家手牌，清点时跳过底牌避免重复计，同时禁用底牌换牌。

界面顶部有常驻「牌堆完整」横幅，实时显示体检结果；异常时列出多出/缺失的牌。

### 14.2 交互细节

- 换牌：面板里每张牌是一个 chip（红色花色 / 王金色 / 主牌描金边）。点一张进入选中态，再点**另一区域**的任意一张即完成交换；同区域点击只是改选或取消。
- 安排进张：选座位 + 从 54 种牌下拉里选（每项显示还能安排几张，排满 2 张自动禁用），可叠加多条；安排是**一次性的**，下一局发牌时生效并写进事件日志（「调试安排生效：右家 ♠A、对家 大王」）。
- 调试操作不影响对局推进：AI 下一手会拿着换过/安排过的牌照常决策，跟牌校验、甩牌判定、结算全走原有规则，不需要任何特殊分支。
