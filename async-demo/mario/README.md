# 超级马里奥 · 蘑菇王国（async-demo/mario）

操控马里奥穿越蘑菇王国，突破障碍、击败库巴，拯救碧琪公主。

## 文件结构

```
mario/
├─ index.vue               面板路由：世界地图 / 游戏 / 源码 / 设计文档
├─ constants.js            瓦片、物理、配色、计分、时长
├─ levels.js               3 关 ASCII 关卡 + 金币奖励房 + parseLevel 解析器
├─ game.js                 纯逻辑：物理 / 碰撞 / 状态机 / 敌人 / 道具

├─ draw/renderer.js        canvas 程序化像素绘制（含调试叠加层）
├─ composables/useMario.js 固定步长循环 + 键盘输入 + HUD 同步
```

### 食人花周期

```
idle(缩回埋伏 48~132 帧) → up(20 帧探出到 44px) → hold(顶端停留 90 帧) → down(20 帧缩回) → idle …
站上管口：强制 down 并保持 idle（原版行为），玩家离开后重新计时
```

判定盒高度 = `min(38, rise)`，**rise 越小伤害窗口越小，完全缩回时判定盒高 0 → 不参与碰撞**。所以"缩回 = 安全窗口"，要越过有花的管道就卡这个窗口。

| -------- | ------------------------------------------------------------------------ |

### 中途存档点（无尽关卡）

无尽关卡一关（260 列起，随关数涨到 600 列）按 `宽 ÷ 130` 在关卡里均匀插 1~4 根**绿色小旗**：

- 旗杆 4 格高，非实心，直接撞上去即可激活：旗面变金色 + 闪烁光晕，飘「CHECKPOINT!」，**补 90 秒**
- 之后阵亡 / 按 R 都从最近一个存档点继续（相机同步对位），形态、分数、金币、已顶过的方块保留
- 存档点只认"整根旗杆"：激活时把 4 格瓦片一起标记，重生点统一取**最底格**（脚踩地面那一格），从空中蹭到旗杆中段也不会记成半空重生点
- 进下一关 / 重开本关时清空

关卡越长给的越多：260 列 → 2 个，600 列 → 4 个。HUD 的「路程」百分比可以随时看推进度。

### 隐藏管道 → 金币奖励房

1-1 与 1-2 各有一根紫色隐藏管道，**无尽关卡每层也有 2~3 根**（见下一节）。站上去屏幕会提示「↓ 进入隐藏管道」，按下后马里奥钻进管道（42 帧过场），进入金币奖励房：

| 房间           | 内容                                            |
| ------------ | --------------------------------------------- |
| 金币奖励房 · 地下金库 | 三层砖台 + 19 枚金币 + 3 个问号块 + 1 个超级蘑菇块             |
| 金币奖励房 · 三层钱塔 | 逐级向上的悬空钱塔（每级落差 2 格）+ 13 枚金币 + 3 个问号块 + 1 个蘑菇块 |

- **哪根管道进哪个房间**：`列号 % 房间数` 决定，同一根管道反复进出始终是同一个房间，不会"换个地方"
- **共性**：46 列宽（约 1.5 屏）、无敌人、每层都在上一层的跳跃范围内（落差 ≤ 2 格）、都能通过 BFS 校验"出生点 → 出口管口"
- **出口**：最右端金色管道，站上去提示「↓ 回到蘑菇王国」，按下后回到**你进入时的那根管道口**（坐标、形态、已顶过的方块、剩下的敌人全部原样保留），接着走原来的路程
- **隔离性**：主关卡做快照（瓦片 / 实体 / 连击 / 剩余时间）压进 `g.stack`，房间是独立小场景（`level.bonus = true`：不画旗杆、不触发过关、换地下背景）；出来时弹栈还原
- **一次性**：每根隐藏管道只能钻一次。按下 ↓ 的瞬间整根管道的瓦片就降级成绿色普通管道（`W → p`），出来后站回去既没有 ↓ 提示也进不去，不能无限刷金币；重进本关才会重新变回紫色
- **成长只增不减**：房里吃到的蘑菇 / 火花、拿到的星星，出来**不会被进房前的快照回滚**（形态取「进房前 vs 出房时」更强的那个）。金币、分数、命数本来就不在快照里，自然保留
- **验证**：故事 1-1 / 1-2、无尽第 3 层都跑过「进入 → 走到出口 → 出来 → 原地反复按 ↓ 120~150 帧」的完整闭环，确认不再二次进入、返回坐标锁在同一根管道口；形态矩阵（`small/big/fire` 进房 × 房内 `big/fire` 成长 × 房内阵亡 × 房内按 R）全部保持不倒退；2500 帧边跑边按 ↓ 无异常
- **容错**：房间里阵亡会被"踢回"原路（只掉 1 条命，主关卡进度不丢）；房间里按 R 重来也会先退回主关卡
- **不重复刷**：房间里的时间不扣（出来时恢复进入前的剩余时间）

生命系统：受伤掉形态，小马里奥受伤才掉命；掉坑直接掉命。掉命后**从最近存档点（没有就是本关起点）重来**，保留分数、金币与形态，生命耗尽才 GAME OVER。

## 无尽关卡生成

`generator.js` 用 mulberry32（seed + 关卡号）确定性随机，按段拼接：

- 段池：`flat / bricks / pipe / gap / platform / stairs`，难度 ≥2 追加 `move`（移动平台），≥1 追加 `sky`（空中敌人）
- 难度随关卡号提升：地图变长（**260 → 600 列**）、坑更宽、敌人更密、出现食人花（`diff ≥ 1` 时 35% 概率）与投怪手
- **食人花管道**：`segPipe` 已在生成，第 3 层起出现（实测 26 层里 21 层有），管高 ≤ 3 保证能越过
- **隐藏管道**（通向金币奖励房）：段生成之后、撒存档点之前，由 `placeWarpPipes` 按 `1 + ⌊宽/240⌋` 根插入（260 列 → 2 根，600 列 → 3 根），均匀分布在 `w·i/(n+1)` 附近并左右各抖动 26 列找第一个合格位置。合格条件：管道占的 2 列 rows 7~~12 全空、**左右各 3 列必须是实地**（不贴坑、不贴砖墙），管高 2~~3 格可直接跳上去站住，管口前 `rows 7~11` 强制挖空，60% 概率在管口上方撒一串金币做视觉引导。先放管道再撒存档点——被管道占的列自动不满足存档点的净空条件，两者不会打架
- 硬约束：**坑宽 ≤ 4、管道高 ≤ 3、平台落差 ≤ 4、段间至少 5 格实地**
- 起点留 14 列跑道，保证第一个坑之前有加速空间；相邻两段不允许同类，坑洞更是强制换段
- **坑洞的四条安全规则**（都是踩过坑才加的，见踩坑记录 13~15）：
  1. 坑前 6 列、坑后 3 列一律铲平（拆掉台阶/砖墙），保证能全速起跳、落地不撞墙
  2. 坑前 6 列到坑后 2 列挖空 rows 7~11（跳跃走廊），杜绝"砖块天花板 + 紧接一个坑"的死局
  3. 坑上方**只撒金币**不放实心平台 —— 平台会挡住跳跃弧线把人顶回坑里
  4. 每个坑自己再留 4 列落脚地，避免连着两个坑形成"一格孤岛"
- 生成后跑 **BFS 可达性校验**：以"站立点"（脚下实心 + 自身两格净空）为节点，边 = 行走（±1 格）与跳跃（|dx| ≤ 5、上升 ≤ 4 格、下降 ≤ 4 格），跳跃走廊按"玩家已进入上升段、比起跳点高 2 格"做保守通道检查；不可达时自动修补（清掉断点障碍并补地面），最多修 40 次
- 最后按宽度撒 1~4 个中途存档点（见上一节）

## 调试系统

**开启**：`~` 键 或 HUD 右上角「🛠 调试」按钮。面板固定在右侧，默认**打开即暂停**（面板内可关掉），避免点按钮时角色掉坑。

状态只有一份：`useDebug` 里的 `reactive flags` 在 `createGame({ debug })` 时直接赋给 `game.debug`，逻辑层读 `g.debug.*`、面板 `v-model` 绑同一对象 —— 不存在"面板改了逻辑没跟上"的双份状态。

| 分区  | 能力                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------- |
| 关卡  | 上/下一关、下拉选关、跳到指定关（无尽模式按层号）、🏁 直达旗杆、✅ 立即通关、± 格传送（默认 10 格）、重开本关、🪙 直接进金币房                                            |
| 角色  | 形态切换（小/超级/火力）、生命 ±/补满、金币 +1/10/50/100（自动折算加命）、分数 +1000/10000/清零、时间 +30/+100/补满、头顶生成 🍄🌸⭐1UP、给/清无敌星               |
| 开关  | **无敌**（不掉血 + 碰怪秒杀 + 掉坑自动救回 + 时间耗尽补满）、**穿墙飞行**（↑↓←→ 自由移动，Shift 加速）、冻结敌人、冻结时间、碰撞盒 / 瓦片网格 / 状态信息、倍速 0.5 / 1 / 2 / 3x |
| 敌人  | 💀 秒杀全场                                                                                                           |
| 运行时 | 坐标 / 瓦片 / 速度 / onGround / 关卡尺寸 / cam / 敌人数的实时读数                                                                   |

实现要点：

- **跳关**走 `loadLevel`（与正常过关同一条路径），并清空场景栈 / 奖励房，避免带着金币房快照换关。
- **传送**用"从上往下扫到第一个 `solid(ty) && !solid(ty-1)`"取地表行，落到地面而不是卡进天花板或掉到地下层。
- **无敌**复用 `star` 机制（每帧续 30 帧），因此视觉上就是星星闪烁，且 `playerVsEnemies` 的"碰怪即杀"自动生效；掉深渊 / 时间耗尽分别走 `rescue` 与补满时间，不会中断调试。
- **飞行**在 `updatePlayer` 里提前 return：无重力、无碰撞，`x/y` 直接 clamp 到关卡边界。
- **倍速**改的是主循环每帧消耗的时间片（`FIXED / speed`），物理仍是固定 60fps 步长，加速不会改变跳跃手感。
- **叠加层**在 `drawScene` 末尾绘制：网格（每 5 列标列号、实心瓦片淡红）、碰撞盒（敌人粉 / 玩家绿 / 道具黄 / 平台紫 / 旗杆判定区青）、运行时文字；godMode 金框、flyMode 青框常驻。
- 面板输入框获得焦点时，`keydown` 会跳过游戏按键与 `~` 开关，打字不会误触。

## 踩坑记录

1. **新增物理字段必须同步 DEFAULT_CONFIG 式的常量表**：本项目是常量集中式，`holdGravity` 从 0.34 调到 0.45 后才得到 4.5 格跳跃高度，所有关卡/生成器的约束都基于该实测值推导。
2. **限速不能只做"减速"**：`vx += accel` 后再 `vx -= 0.34` 会净增 0.3/帧导致无限加速到 9.6；正确写法是"未超速就封顶、已超速才缓慢回落"。
3. **可达性校验不能把实体字符当墙**：ASCII 里的 `@ g k o` 是出生点/敌人/金币，判定阻挡应只认 `SOLID` 集合，否则起点直接判不可达。
4. **跳跃通道检查要按"上升后的高度"取样**：用起跳点行做矩形检查会把"从管道上方飞过"误判为不可达 —— 改为检查 `[min-4, min-2]` 的飞行走廊 + 起终点身体两格净空。
5. **无头测试的跳跃需要"按住"**：起跳帧若 `jump=false` 会被 jumpCut 截断成 20px 小跳，测试机器人要维护 hold 计数模拟按住跳跃键。
6. **落地探测行不能用 `y + h - 1`**：脚底正好贴在瓦片顶边时，`-1` 让探测落到上一行空气 → 判定失败 → 实体继续下沉 0.6~1.4px，下一帧才被拉回。结果是 `onGround` 每两帧翻转一次（站立时也在翻），渲染里"手"在 `bodyY+6 / bodyY-4` 之间 30Hz 抽搐、走路动画两帧才动一格。改为 `Math.floor((y + h) / TILE)` 取精确脚底行。
7. **零高度碰撞盒会误判**：`aabb` 用纯不等式，退化盒（h=0）会命中"跨过该 y 线"的任何实体。食人花隐藏时 rise=0 → 判定盒正好压在管口顶面，玩家每帧微沉 0.6px 就被判中 → 小马里奥一跳上管口即死。`aabb` 增加 `w/h <= 0` 直接返回 false 的守卫。
8. **管道与坑洞之间要留安全距离**：满速满跳水平约 300px（≈9 格），1-2 原本"管道 → 7 格 → 4 格坑"，跳过管道会正好落进坑里；把该坑右移 6 格后为 13 格实地。
9. **倒计时不能用全敌人共享的 `e.t`**：`updateEnemies` 每帧对所有敌人 `e.t++` 做动画计时，食人花在 wait 阶段又 `e.t--`，净变化 0 → **倒计时永远走不完，花再也不探头**。这类"每帧自增 + 局部递减"必须用独立字段（`e.wait`）。症状很像"随机才出发"，实际是 100% 卡死。
10. **切场景会换掉 `g.player` 对象**：`resetEntities` 重新赋值 `g.player = {...}`，测试脚本里缓存的旧引用会变成孤儿对象（改它不影响游戏、读它永远是静止值）。要么每帧重新取 `g.player`，要么在切换后重新绑定。
11. **ASCII 关卡行会整体偏移一列**：手写/粘贴 100+ 列的行极易错位 1 格，而管道是"多列重叠"的结构 —— 错一列就变成伸出的屋檐，玩家站在下面头顶是实心，**原地起跳直接撞头无法动弹**。改完关卡一定要用脚本打印每行的字符索引，确认同一根管道上下行的列完全一致。
12. **奖励房的出口管道不能孤零零放在平地上**：测试机器人（和急性子玩家）会以全速跳过管口，落进管道右边的死角。让砖块阶梯的顶部与管口同高、右边再接一堵墙，走到尽头自然就站上去了。
13. **坑洞上方不能放"中继平台"**：看似给玩家一条可选路线，实际是块天花板 —— 玩家在坑边缘起跳，头刚抬 4px 就撞到平台底面，跳跃被截断，必掉坑。要奖励就撒金币（非实心）。
14. **坑前必须有净空**：`bricks` 段在 row 9 铺一整行砖，紧跟着一个坑的话，玩家在砖块底下起跳会被顶回来（上升 68px 就撞头，而跨越 3 格坑需要完整 144px 的滞空）。解法：砖块段尾部留 3 列空地 + 坑前 6 列强制挖空 rows 7~~11。这个坑在手工 1-2 / 1-3 里也各有 1~~2 处，已按同样规则修掉（管道左移 / 平台缩短）。
15. **两个坑之间至少 4 列实地**：段循环原本 `x += max(4, used)`，坑段返回 `gw+1`，于是一根 1 列的地面就能夹在两个坑中间 —— BFS 判"可达"（它能走过去），但玩家根本站不住。现在坑段返回 `gw+4` 且强制不连续出两个坑。
16. **评测机器人别为敌人起跳**：踩怪的反弹只有 8.2（完整跳是 11.6），滞空短一截，正好在坑前踩怪就会跳不过坑。测试机器人开了无敌，直接无视敌人、只按墙/坑信号起跳更稳。另外"墙"要**逐列扫描**（单点采样会跨过 2 列宽的管道），且探测距离要 ≥96px —— 贴着墙再跳会被 `moveX` 把 `vx` 清零，还没升过墙顶就撞上侧面。
17. **改完关卡/生成器要跑"客观体检"而不是只看机器人**：扫地面行统计每个坑的「宽度、坑前连续实地列数、助跑段 rows 9~12 是否实心」，比让机器人实跑更能定位问题（机器人会随启发式改动忽好忽坏）。
18. **调试开关不能做成两份状态**：`game` 是普通对象（纯逻辑层不引入 vue），面板若直接 `v-model` 绑 `game.debug.*`，值会改、功能会生效，但**渲染不刷新**（非响应式属性不触发依赖）。做法是把 `reactive(flags)` 在 `createGame({ debug })` 时塞进 `game.debug`，面板与逻辑层共用同一个对象。
19. **稳定性断言要排除死亡动画**：`dying` 状态下角色自由落体出场（84 帧最多下落 1000+px），"y 越界"统计必须加 `!p.dead`，否则正常的死亡动画会被算成 bug。
