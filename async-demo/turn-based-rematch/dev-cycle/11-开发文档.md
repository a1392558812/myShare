# 第 11 期 · 立绘 painter B（星君 / 四象 / 星宿）

> 阶段 C ｜ 预估 1 天 ｜ 状态：未开始 ｜ 依赖：10

## 目标

7 位星君、4 只四象、28 只星宿都能用同一套 painter 画出来；同族只靠主色与两三个外形参数派生，不写 39 套代码。

## 需求来源

README §3.4（星君 168×208 / 四象 150×120 / 主色来源）、§11.3（星君列表）、§11.5.1（28 宿表）、§15.1（帧率与立绘缓存）

## 本期做什么

- [ ] 星君：复用 `drawUnit`，尺寸 168×208、锚点 (84,204)，7 位按五行主色 + 1 个标志物（北斗七星位）派生；动作帧同 12 个（`retreat/summon` 可复用 idle）
- [ ] 四象：兽形横长 150×120、锚点 (75,116)，青龙青 / 朱雀赤 / 白虎白 / 玄武黑，4 个外形参数（角、翼、尾、甲）
- [ ] 星宿：120×96 兽形，按 28 宿的"五行 + 定位"两个维度派生（五行定主色，定位定体型），不逐只定制
- [ ] 离屏预渲染：每个 `(kind, palette, action)` 组合首次绘制时缓存到 `OffscreenCanvas`（不支持则退化到普通 canvas），避免每帧重画路径
- [ ] `draw/registry.js`：`getPainterSprite(kind, opts)` 统一入口，带缓存 key（`kind|主色|动作|帧`）
- [ ] 调试页扩到"7 星君 + 4 四象 + 28 星宿"三排，全部 `idle` 播放

## 本期不做（防膨胀）

- 不做星宿的差异化外观（28 只长得像没关系，只靠五行色 + 体型区分）
- 不做四象的出场/救人特效 → 第 15 期
- 不做立绘随装备变化 → 明确不做
- 不做 Boss 皮肤、不做季节变体 → 不在需求内

## 验收

1. 三排共 39 个单位同屏播放 `idle`，中端机 ≥ 60fps（帧率读数来自第 01 期那行调试文字）。
2. 7 星君主色肉眼可区分；4 四象一眼能认出青龙/朱雀/白虎/玄武。
3. 28 星宿同屏不重样到"完全一致"的程度（五行色至少分 5 组）。
4. 首次进入有可感知的预渲染耗时（≤ 200ms），之后切换动作不掉帧。
5. 缓存命中后每帧不新建 `Path2D`（在调试页打印每帧创建数 = 0）。
