# 第 02 期 · 存档框架与角色创建

> 阶段 A ｜ 预估 1 天 ｜ 状态：未开始 ｜ 依赖：01

## 目标

第一次进游戏能创建角色（选门派 + 道号），刷新页面后角色还在；6 个存档 key 各自独立、坏一个不影响其余。

## 需求来源

README §14.2（数据对象）、§14.3（数据口径）、§14.4（保留与清理）、§16.3（存档解析失败）、§13.1（角色创建界面）

## 本期做什么

- [ ] `core/save.js`：统一读写 6 个 key —— `tbr.player` / `tbr.equip` / `tbr.pet` / `tbr.tower` / `tbr.bag` / `tbr.codex`
- [ ] 每个 key 自带 `version`；`load(key)` 解析失败或版本不匹配 → **只重置该 key**，日志记录，不阻塞启动
- [ ] `player` 初始结构：道号、门派、等级 1、经验 0、`expPool` 0、属性点、相性五项 0、`daoBought` 0、灵石 0、当前层 1
- [ ] 角色创建页（DOM）：门派 5 选 1（金木水火土）+ 道号输入（1–8 字，非空），选门派时显示该门派起始法术与相性软绑定提示
- [ ] 建号后写入 `tbr.player`，其余 5 个 key 也初始化（空数组 / 默认对象），保证"删任一 key 不影响其余"
- [ ] 简易主界面 shell：地图区（占位色块）+ 底部三个占位按钮（配置 / 商店 / 图鉴），点击只弹 toast "未开放"

## 本期不做（防膨胀）

- 不做门派法术的真实数值与战力 → 第 08 期
- 不做属性点分配 → 第 24 期；相性面板 → 第 26 期
- 不做存档加密、云同步、多档位 → 不在需求内
- 不做 `visibilitychange` 立即写盘 → 第 21 期（有扫荡累计后才需要防丢）

## 验收

1. 首次进入出现创建页；道号留空时不能提交；提交后进入主界面。
2. 刷新页面直接进主界面，不重复建号。
3. 手动删掉 `tbr.equip` 后刷新：只剩装备数据重置，等级/门派/道号都还在。
4. 把 `tbr.player` 改成非法 JSON 后刷新：不白屏，回到创建页并打印一条日志。
5. `localStorage` 里 6 个 key 同时存在。
