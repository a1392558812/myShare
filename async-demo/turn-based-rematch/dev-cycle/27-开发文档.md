# 第 27 期 · 装备数据层与归属

> 阶段 F ｜ 预估 1 天 ｜ 状态：未开始 ｜ 依赖：26

## 目标

18 个槽位（人 9 + 宠 9）的数据结构立起来：能创建一件装备、能穿、能脱、能算出它给穿戴者加了多少；同一件装不能同时被两人穿。

## 需求来源

README §7.1（槽位与归属）、§7.2（各档白板）、§7.8.1（战斗配置锁）、§9.11（宠物装备）、§14.2（`equip` 字段）、§17.2 R-31

## 本期做什么

- [ ] 槽位定义：9 个槽位名称与顺序**逐字照 7.1 表**，不自创；玩家与宠物共用同一套槽位定义
- [ ] 装备实例：`{ instanceId, slot, tier, quality, stats, enhance, gems[], affixes[], wornBy }`
- [ ] 白板：`tier = ceil(L_敌 / 10)`，血量 `126 × t^1.2`、物攻 `35 × t^1.2`（照 7.2，一次算清，不手填）
- [ ] 穿戴/卸下：`equipItem(unitId, instanceId)` / `unequip(unitId, slot)`；同一 `instanceId` 只能有一个 `wornBy`
- [ ] 加成结算：`getEquipBonus(unit)` 汇总该单位 9 件的白板 + 强化 + 词条 + 宝石（本期只累加白板，其余返回 0 占位）
- [ ] 装备仓库 60 格（人宠同一张表，靠 `wornBy` 区分），与背包 24 格分离
- [ ] 战斗锁：战斗中穿脱一律拒绝，返回"战斗中不可调整配置"
- [ ] 存档：`tbr.equip` 存整张装备表（含 `wornBy`），刷新后穿戴关系保持
- [ ] 探针：给 L=50 的玩家穿 9 件 5 档 +0 装，核对 7.2 的合计值

## 本期不做（防膨胀）

- 不做品质与词条 → 第 28 期（本期 `quality` 固定 `凡`、`affixes` 空）
- 不做强化/镶嵌/洗髓 → 第 29 / 30 期
- 不做套装 → 第 31 期
- 不做掉落与邮箱 → 第 32 期
- 不做装备面板 UI → 第 33 期（本期用调试命令穿脱）

## 验收

1. 18 个槽位全部可穿可脱，槽位名与 7.1 表一致。
2. 把同一件装备先给玩家再给宠物：玩家槽位自动空出，或操作被拒（二者选一，行为必须一致且写进补充需求）。
3. 50 级玩家穿 9 件 5 档 +0：气血/物攻增量与 7.2 表一致。
4. 战斗中穿装备被拒并提示；脱装备同样被拒。
5. 刷新页面后 `wornBy` 关系不丢。
