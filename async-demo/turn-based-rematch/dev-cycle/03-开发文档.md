# 第 03 期 · 数值表与单位工厂

> 阶段 A ｜ 预估 1 天 ｜ 状态：未开始 ｜ 依赖：02

## 目标

所有数值只存在于 `config/`，所有单位只由 `createUnit()` 生成；跑一个 Node 脚本能把 12.1 的复算口径和 12.3 的星君锚点原样算出来，误差 0。

## 需求来源

README §12.1（复算口径）、§5.4（玩家属性）、§9.2（宠物属性）、§11.3（星君系数）、§11.5.1（星宿系数）、§6.3（抗性公式）、§5.6（道行定价）、§16.2（模块约束）、§16.3（启动自检）

## 本期做什么

- [ ] `config/elements.js`：金木水火土 + 相克环 + 系数 1.25 / 0.85 / 1.00
- [ ] `config/units.js`：定位系数（物理/法术/高速/肉盾/控制）、星君 7 位基础系数、星宿 28 只（种族 / 五行 / 定位 / 等级偏移 / 五维系数）
- [ ] `config/growth.js`：`EXP_TO_NEXT`、每级 4 点、道行 `4×等级`、道行购买定价 `round(20 × L^0.7 × (1 + d/200))`
- [ ] `config/affinity.js`：五项相性、单一上限 30、溢出后 60/90/120/200、抗性 `R/(R+P)`、`P = 20 + 0.04 × 攻方等级`
- [ ] `config/rarities.js`：装备 5 品质（凡 / 灵 / 玄 / 天 / 仙）、宠物 4 阶（成长与初始资质范围）
- [ ] `core/unit.js`：`createUnit(kind, level, opts)`，`kind ∈ player | pet | starLord | fourSymbol | mansion`；统一字段 `{ id, kind, level, hp, maxHp, atk, matk, def, spd, dao, element, role }`
- [ ] `core/stats.js`：玩家 / 宠物 / 星君 / 星宿 四套属性公式；相性→抗性→减伤的纯函数（UI 后置，先给内核用）
- [ ] `core/validate.js`：启动自检 —— 缺字段、系数为空、定位未注册一律抛错（`?debug=1` 抛错，正式环境降级为 0 并打日志）
- [ ] 写一个 `.tmp/check.mjs` 探针（不入库）：复算 12.1 口径下 L=1/50/100 的玩家与宠物面板 + 12.3 中任取 3 位星君，与文档逐格对比

## 本期不做（防膨胀）

- 不做装备加成（`equipBonus` 一律 0）→ 第 27 期
- 不做相性与加点对属性的影响（`assign` 用推荐比例占位，`affinity` 全 0）→ 第 24 / 26 期
- 不做任何绘制与交互 → 第 10 期起
- 不做星君技能/四象随行的行为逻辑 → 第 18 期

## 验收

1. `.tmp/check.mjs` 输出的玩家/宠物面板与 §12.1 口径逐项一致（浮点允许 0.01）。
2. 12.3 抽样 3 位星君的 HP/ATK 与文档数字一致。
3. `createUnit('mansion', 11)` 的等级 = 当前层数 + 该宿偏移（用 4 只不同偏移的宿各验一次）。
4. 把 `config/units.js` 里某只星宿的定位删掉，`?debug=1` 启动即报错；去掉参数则不报错、面板该值为 0。
5. `core/` 下不出现任何 `document` / `canvas` / `import ... from '../stage'`。
