## 五、拆分口径（防止膨胀的四条硬规则）

1. **一期的验收必须能一句话说清**：例如"点星宿 → 走到 90px → 弹对话 → 开始战斗"，而不是"实现星宿系统"。说不清就说明还在塞多个闭环。
2. **一期只碰两层**：`core` / `stage` / `draw` / `components` 里最多改动两个目录；跨三层说明这期在"顺手重构"，砍掉。
3. **"顺手"一律不进本期**：调试面板、性能优化、动画润色、额外文案、平衡微调，都各自有归属期（42 / 43），不塞进功能期。
4. **数值只信 README 第 12 章**：任何一期都不许"觉得太强就改一点"；改动必须先回 README 改公式，再重算整表，再进开发。
