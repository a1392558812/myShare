## 目标

把内核状态画成一张能看的战斗画面：6 个槽位站好、按纵深排序、血条与脚环正确、倒地的人还躺在那儿。

## 需求来源

README §3.2（九层渲染）、§3.3（槽位坐标与镜像）、§3.11（性能预算）、§9.9（宠物离场）

## 本期做什么

- [ ] `stage/render.js`：`renderBattle(ctx, battle, t)` 按 L0→L8 顺序画，**本期只实现 L0–L4 + L7 的血条部分**（L5/L6 特效、L7 面板、L8 全屏层分别在第 14 / 13 / 15 期）
- [ ] L0 背景 / L1 装饰 / L2 擂台圈与站位脚印 / L3 阴影与脚环与倒地标记 / L4 单位（按 `slot.y` 升序）
- [ ] 6 槽坐标照 3.3 写死：S1(392,596,1.0) S2(300,566,0.88) S3(232,540,0.78) / E1(888,596) E2(980,566) E3(1048,540)；`E(n).x = 1280 − S(n).x` 用公式算，不写两遍
- [ ] 单位绘制：立绘按 `scale` 缩放、脚底对齐锚点；血条在头顶（宽 72、高 6、底黑、红填充、缺血留底）；等级与名字小字
- [ ] 倒地：立绘切 `down`、脚下椭圆拉长、头顶血条转灰并显示"倒在"；**不淡出**
- [ ] 宠物离场：`retreat` 播完直接不画（本期先按内核的瞬间离场处理，动画在 15 期接）
- [ ] `components/BattleCanvas.vue`：只做 canvas 生命周期 + 尺寸同步 + 每帧 `renderBattle`，不写业务判断
- [ ] 静态调试场景：`?debug=1&scene=battle` 直接进一场假战斗，方便逐槽目视

## 本期不做（防膨胀）

- 不做指令面板、日志、快捷栏 → 第 13 期
- 不做命中测试与点击 → 第 13 期
- 不做动作状态机（谁在 attack / hurt）→ 第 14 期由事件驱动

## 验收

1. 六个槽位坐标与 3.3 完全一致（对照截图量一次）。
2. 把 S1 与 E1 的 `slot.y` 对调后，遮挡关系随之改变（证明排序生效）。
3. 玩家倒地后立绘仍在地面、血条变灰，**没有被清空或淡出**。
4. 星宿战只有 E1 有单位，E2/E3 完全不绘制、不留空框。
5. 1280×720 下 60fps；把 6 个单位全换成星君尺寸仍 ≥ 55fps。
