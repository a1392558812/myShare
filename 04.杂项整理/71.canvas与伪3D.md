# canvas与伪3D

## "伪"在哪

真正的3D渲染管线里，每个像素是一条射线和一个三角形的求交；而1992年《德军总部 3D》用的方法更取巧：世界是一张二维网格地图，墙都是单元格的边,于是屏幕不再是一个平面，而是被切成一根根竖直的细条，`屏幕上的第x列像素 = 从眼睛出发、朝那个方向射出的一根射线`,射线走格子，撞到墙，就有了"这一列看到多远、看到什么样的墙"，再按距离画一条竖直的矩形。距离越远，矩形越矮，透视就这么来了，完全不需要矩阵。

整个画面只有四部分：

1. 一张地板/天花板底图（有透视，才有"站在地上"的感觉）
2. 一堆按距离缩放的竖条矩形（墙）
3. 一把画在屏幕右下角的枪（屏幕空间贴图，不参与 3D 投影）
4. 一点点 HUD（准星、小地图、弹药）。

## 网格求交

最朴素的做法是让射线以小步长前进，直到踩进墙格。问题是：步长小了，一根射线要走几十步；步长大了，会穿墙，正确解法是 **DDA（Digital Differential Analyzer）**：不要"走"，而是"跳格子边界"。射线每次只关心下一个撞到的是竖线（x 方向边界）还是横线（y 方向边界），谁先到就跳到谁那。先算两个固定量——射线穿过一个格子需要的距离，以及到第一条边界的距离：

```ts
const deltaDistX = rayDirX === 0 ? Infinity : Math.abs(1 / rayDirX);
let sideDistX =
  rayDirX < 0
    ? (originX - mapX) * deltaDistX
    : (mapX + 1 - originX) * deltaDistX;
```

然后循环里只做一件事：比较两条边界距离，走更近的那条，并把命中的面记成 `side = 0 | 1`。

```ts
if (sideDistX < sideDistY) {
  sideDistX += deltaDistX;
  mapX += stepX;
  side = 0;
} else {
  sideDistY += deltaDistY;
  mapY += stepY;
  side = 1;
}
```

一格一格跳，命中墙时最多 16 步，且绝不会穿墙,这就是 DDA 的全部。

### 第一个坑：鱼眼畸变

一开始我图省事，拿了"射线起点到命中点的直线距离"去算墙高，走两步就发现画面像鱼眼镜头：屏幕边缘的墙被明显拉长。原因是，屏幕上同一列对应的墙如果离视轴越远，欧氏距离越大，但它在垂直于摄像机平面的方向上的深度其实没变，不该变矮，正确的量是"垂直距离"，DDA 里天然就有——把刚跨过的那一段减掉：

```ts
const distance = side === 0 ? sideDistX - deltaDistX : sideDistY - deltaDistY;
```

换成这个值之后，画面立刻"正"了：正前方的墙是矩形，侧面的墙是斜的梯形。

### 顺手拿一个纹理坐标

命中时再算一下命中点落在墙面的哪一侧，取小数部分，就是贴图的 U 坐标：

```ts
const hitCoord = side === 0 ? hitY : hitX;
const wallCoord = hitCoord - Math.floor(hitCoord); // ∈ [0, 1)
```

`wallCoord ∈ [0, 1)` 后面被用来画砖缝，一格墙正好一块"贴图"，不需要加载任何图片。

## 从距离到画面：墙切片怎么画

有了垂直距离，墙高是一行公式：

```ts
const sliceHeight = Math.min(
  height * 3,
  (height * WALL_HEIGHT_RATIO) / Math.max(hit.distance, 0.05),
);
const drawStart = (height - sliceHeight) / 2;
```

含义是：**距离为 1 的墙，恰好占满屏高的 `WALL_HEIGHT_RATIO` 倍**。`1.35` 是我试出来的手感值，等于 1 时墙只有一人高，画面上下大片空洞，很像"悬浮的栅栏"；调到 1.35 后空间才有围合感。`Math.min(height * 3, …)` 是贴脸时的保险，不然玩家撞到墙的瞬间会画出几十倍屏高的矩形。方向感也在这里：`side` 为 1（南北向墙面）时整体压暗到 0.76，两组墙面立刻能区分开，比加光照便宜得多。

### 让墙不那么"塑料"

1. **距离雾**：所有墙色都朝同一个雾色混合，混合比例随距离非线性上升。远处的墙会自然融进背景，而不是硬边切断。
2. **墙根压暗 + 墙顶高光**：每个切片补两个矩形（底部 40% 压暗、顶部 6% 提亮），代替逐列渐变，成本几乎为零，但体积感明显。
3. **程序化砖缝**：`wallCoord` 靠近 0.25 的整数倍时画一条竖向暗线，再在切片高度上等分两条横线；透明度按雾浓度衰减，远处自动"糊掉"。

这里也有个小教训：砖缝一开始按 4×4 画，结果是整面墙变成一张方格网，看起来像半透明的铁丝网。改成 4 竖 + 2 横、并且把透明度从 0.3 降到 0.26 之后，才终于像"墙"。

## 地板与天花板：一行像素一个距离

这是整篇里唯一需要真正推导的地方，也是"像 3D"和"像栅栏"的分界线。墙画完了，但屏幕上下还剩两大片纯色渐变，人会觉得墙是浮在空中的。要让地板有透视，必须真的知道屏幕上每一行对应地面上的多远。核心是：相机水平时，地面上"与视轴深度相同"的点构成一个平面，投影到屏幕上就是一条水平线，换句话说就是“同一行扫描线，整行的世界距离完全相同”，那逐行算距离、逐列只做坐标累加即可。距离来自相似三角形：

```ts
// 眼睛高 0.5，屏幕焦距为 height * WALL_HEIGHT_RATIO
const distance = (EYE_HEIGHT * height * WALL_HEIGHT_RATIO) / (y - horizon);
```

先按站立眼高 0.5 推导,加了跳跃与下蹲后,这个变量为随时间变化的 `player.eyeHeight`，详见下文《跳跃与下蹲》。然后给这一行准备起点（`cameraX = -1`）和每列增量：

```ts
let floorX = player.x + distance * (dirX - planeX);
const stepX = distance * planeX * (2 / bufferWidth); // 每列固定增量
```

逐像素只做三件事：算棋盘奇偶、取颜色、写进 `ImageData`。棋盘就是半格一块砖：

```ts
const tile =
  (Math.floor(floorX * 2) + Math.floor(floorY * 2)) & 1 ? colorA : colorB;
```

因为整行距离相同，雾色也可以一行只算一次，两种砖色各混一次，逐像素就只剩数组写入。行数 × 列数的循环里没有一个三角函数、没有一个 `Math.pow`，这是它能跑满 60FPS 的根本原因,渲染策略是半分辨率离屏缓冲：内部按 `scale ≤ 0.5`（且宽度不超过 960px）渲染，`putImageData` 之后一次 `drawImage` 放大到全屏，再让 `imageSmoothingEnabled = true` 把块状边缘糊掉。像素级工作量直接降到 1/4，视觉上几乎看不出损失，地板反而更柔和

### 第二个坑：墙脚对不齐

这个坑值得单独说，因为它非常隐蔽：墙的高度公式和地板的距离公式**必须共用同一套常量**。如果墙用 `WALL_HEIGHT_RATIO = 1.35`、地板却按 1.0 推导,ze地面和墙脚的接缝会错开几个像素，看起来像墙"飘"在地板上方，而且贴得越近错得越明显,解决办法是把这几个数字抽成单文件常量: `视野角、墙高系数、列宽、最远距离、眼高` 两边都从这里取,之后无论怎么调手感，地面和墙永远严丝合缝。：

```ts
export const FOV = Math.PI / 3;
export const WALL_HEIGHT_RATIO = 1.35;
export const EYE_HEIGHT = 0.5;
```

## 移动手感：纯函数 + 分轴滑行

输入层只做一件事：每帧产出一个快照。

```ts
interface InputSnapshot {
  forward: number;
  strafe: number;
  turn: number;
  run: boolean;
  jump: boolean; // 空格边沿触发：本帧刚按下才为 true
  crouch: boolean; // Ctrl 按住
  mouseDelta: number;
  mouseDeltaY: number;
  lookVertical: number;
}
```

键盘用一个 `Set` 记录按下集合，鼠标位移只在指针锁定期间累积，`read()` 时一次性取走并清零,不这样做的话，未锁定时的鼠标抖动会被算进转向，画面会莫名自己漂,空格要单独照顾：按下瞬间（此前未按下）才置位一个 `jumpQueued` 标记，`read()` 取走即清零.若把"按住"当跳跃输入，按住空格就成了帕金森式连跳。移动本身是一个纯函数，输入快照加时间步长，返回新的玩家状态：

```ts
const yaw = normalizeAngle(
  player.yaw +
    input.turn * TURN_SPEED * dt +
    input.mouseDelta * MOUSE_SENSITIVITY,
);
```

手感细节：

1. **位移按 `dt` 缩放**，与帧率无关；`dt` 上限钳在 50ms，否则切到后台再回来，一帧的位移足够穿过一堵墙。
2. **斜向归一化**，`W + D` 不会比单独 `W` 快 41%。
3. **分轴求解碰撞**：先试 X 方向，能站住就走；再试 Y 方向。这样贴墙时不会被"卡死"，而是顺着墙面滑行——这是所有第一人称游戏的基础手感。

碰撞体用玩家外接方框的四角采样，近似一个圆形：

```ts
!isSolid(x - r, y - r) &&
  !isSolid(x + r, y - r) &&
  !isSolid(x - r, y + r) &&
  !isSolid(x + r, y + r);
```

半径 0.26，必须小于半格，否则一格宽的门洞就永远过不去。

### 第三个坑：出生点

出生点放在地图左上角一条单格走廊里。结果首帧就贴着 0.5 格外的墙面，整个屏幕一大片纯色，看起来像"渲染坏了"。解决办法这里讨了个巧，把出生点挪到中央大厅、朝向再斜 34° 之后

## 跳跃与下蹲：眼睛高度也是变量

墙高公式和地板公式里都藏着一个"眼高 0.5"。只需把这个常量升级成状态：`PlayerState` 加上 `eyeHeight` 和竖直速度 `verticalVelocity`，每帧做一次最朴素的积分离散：

```ts
verticalVelocity -= GRAVITY * dt;
eyeHeight += verticalVelocity * dt;
if (eyeHeight <= groundHeight) {
  eyeHeight = groundHeight; // 落地
  verticalVelocity = 0;
}
```

起跳就是给`verticalVelocity` 赋一个初速度（2.4，重力取 12，约跳起 0.26 格、滞空 0.4 秒）.下蹲则是把"地面"从 0.5 换成 0.3，并用一个很大的插值系数在站/蹲之间平滑过渡,使得高度不突变，镜头不会抖：

```ts
const groundHeight = input.crouch ? CROUCH_HEIGHT : STAND_HEIGHT;
eyeHeight += (groundHeight - eyeHeight) * Math.min(1, dt * CROUCH_LERP);
```

手感规则：

1. 下蹲移速单独降到 1.2（行走 2.4 / 冲刺 4.2）
2. 下蹲中不允许起跳；跳跃吃上一节的边沿触发，按住空格不会连跳
3. 渲染侧只改两处公式，动：`eyeHeight`：

```ts
// 墙切片：眼睛越高，墙脚越往下沉
const drawStart = height / 2 + pitchOffset - (1 - eyeHeight) * sliceHeight;
// 地板/天花板：各自的透视尺度，跳起时地板"变远"、天花板"变近"
const floorScalePixels = eyeHeight * height * WALL_HEIGHT_RATIO;
const ceilingScalePixels = (1 - eyeHeight) * height * WALL_HEIGHT_RATIO;
```

`eyeHeight = 0.5` 时，站立画面与加跳跃之前逐像素一致。这也是"墙脚对不齐"那一坑的延续：墙脚偏移与地板尺度必须从同一个`eyeHeight` 推导，跳到最高点时接缝才不会裂开

## 第一人称武器：一张离屏画布

枪不参与 3D 投影，它是"屏幕空间贴图"：挂载时把整把AK 连同两只手一次性画进离屏canvas，之后每帧只有一次 `drawImage`,它永远钉在右下角，像贴在镜头玻璃上，俯仰、跳跃都不影响它。离屏绘制的组织方式是"局部坐标系 + 分件叠加"：以枪口为原点、枪管方向为x 轴，先旋转一个倾角，再按 `枪托 → 机匣 → 握把 → 弹匣 → 护木 → 枪管 → 左手 → 右手`的顺序绘制；木纹与金属全靠线性渐变伪造

```ts
ctx.translate(MUZZLE_ORIGIN_X, MUZZLE_ORIGIN_Y);
ctx.rotate(GUN_TILT);
drawStock(ctx);
drawReceiver(ctx); /* … */
drawLeftHand(ctx);
drawRightHand(ctx);
```

贴图按 `devicePixelRatio`（上限 2×）放大一次画完,每帧的定位用枪口锚点：精灵里存了枪口的归一化坐标 `(muzzleX, muzzleY)`，屏幕上希望枪口停在 `(0.64, 0.44)`，反解出贴图左上角——窗口缩放时枪是"从枪口向右下生长"，而不是从角落漂浮：

```ts
const restX = width * MUZZLE_ANCHOR_X - gunWidth * sprite.muzzleX;
```

行走摆动、后坐力、换弹动作全部是围绕这个锚点的平移旋转，几个数字决定"手感"：

```ts
const centerX = restX + gunWidth / 2 + motion.bobX + kickX;
const rotation = -0.035 + motion.recoil * 0.035 + motion.reloadProgress * 0.42;
```

开火时 `recoil` 把枪往右下顶一点并微微上旋，约0.15秒衰减完,换弹是下沉 0.26 屏高、旋转 0.42 弧度再抬起。枪口火焰画在贴图坐标系的枪口点上：`lighter` 混合的径向渐变加四条随机长度的星芒，0.055 秒自然熄灭，武器逻辑本身是一个纯函数状态机——换弹读条、射速冷却（0.095 秒，约 600 发/分）、后坐力衰减都在里面推进，组件只喂按键、收音效事件。弹药显示 `30 / ∞` 没有任何特殊分支：备弹直接存无穷大，换弹永远补满，打空弹匣继续扣扳机就走自动换弹：

```ts
export const RESERVE_START = Number.POSITIVE_INFINITY;
```

## 循环

主循环就是标准的 `requestAnimationFrame`，注意以下细节即可：

- **画布尺寸跟随容器和 `devicePixelRatio`**（上限 2×），用 `ResizeObserver` 而不是 `window.resize`，组件放进任何布局都不会糊。
- **HUD 节流**：FPS、坐标、朝向每 500ms 才写一次响应式对象。如果每帧都写 `reactive`，Vue 的更新开销会白白吃掉渲染预算。
- **卸载即回收**：`cancelAnimationFrame`、移除 `keydown` 监听、断开 `ResizeObserver`、`dispose()` 输入（内含退出指针锁定）。

```ts
const dt = Math.min((timestamp - lastTimestamp) / 1000, 0.05);
```

这一行几乎出现在所有游戏循环里，但漏掉它的人依然很多。

## 性能

- 墙：宽度 / 2 根射线，每根 1~6 个 `fillRect`，`1280` 宽约 640 列，一帧 2000 出头个矩形；
- 地板/天花板：半分辨率 `ImageData`，`1280 × 820` 约 32 万像素，逐像素只有一次位运算 + 三个通道写入，缓冲对象复用、不重新分配；
- 武器：离屏贴图只在挂载时画一次，渲染循环里只有 1 次 `drawImage` 加平移旋转，枪口火焰是 1 个径向渐变 + 4 条线段；
- 渲染循环内零 `createLinearGradient`、零逐像素三角函数（渐变都发生在离屏贴图的一次性绘制里）。

## 拓展展

- **墙面贴图**：`wallCoord` 已经是现成的 U 坐标，把砖缝换成 `drawImage` 的纹理竖条即可；
- **精灵（道具/敌人）**：按每个射线命中的距离做深度排序，再用摄像机变换投影，本质是"带透明通道的墙列"；
- **可开关的门**：格子值换成对象，射线遇到"开着的门"继续步进；
- **移动端**：把键盘输入换成虚拟摇杆加触摸滑动转向，渲染层完全不用动。
