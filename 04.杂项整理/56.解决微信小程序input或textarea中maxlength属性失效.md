# 解决微信小程序 input/textarea 的 maxlength 失效

uni-app [官方文档](https://uniapp.dcloud.net.cn/component/textarea.html#textarea)对 `textarea` 的描述是：

> maxlength Number 140 最大输入长度，设置为 -1 的时候不限制最大长度

但在微信小程序端，`input` 和 `textarea` 的 `maxlength` 属性并不可靠，存在超长的情况。

## 问题复现

以下写法可 100% 复现：

```html
<template>
  <textarea v-model="inputStr" placeholder="请输入" maxlength="100" />
</template>

<script setup lang="ts">
  const inputStr = ref("");
</script>
```

**复现方式一（输入法组词）**

先键入 99 个数字 `1`，切换到中文输入法键入 `aaaaaa`，选中候选词 `啊啊啊啊啊啊`，再点击空白处使输入框失焦。此时输入框内容为 `1` + `啊啊啊啊啊啊`，实际长度 105，已超过 100 的限制。

**复现方式二（粘贴）**

先键入 99 个数字 `1`，然后向输入框粘贴一段较长的文字，输入框内容同样会突破 100 的限制。

两种方式本质上都是绕过了组件的原生长度拦截，把超长内容直接写进了 `value`。

## 解决办法

放弃原生 `maxlength`，改为受控写法：绑定 `v-model`，在 `@input` 中手动截断。

```html
<template>
  <textarea v-model="inputStr" placeholder="请输入" @input="handleInput" />
</template>

<script setup lang="ts">
  const MAX_LENGTH = 100;

  const inputStr = ref("");

  const handleInput = (e: any) => {
    const value = e.detail.value;
    if (value.length > MAX_LENGTH) {
      nextTick(() => {
        inputStr.value = value.slice(0, MAX_LENGTH);
      });
    }
  };
</script>
```

### 为什么要 nextTick

小程序的 `input` / `textarea` 属于半受控组件，视图层已经持有了超长文本。如果在同一个 tick 内立即写回截断后的值，由于响应式数据刚被赋成同样的超长内容、diff 结果可能被判定为「无变更」，这次赋值会被丢弃，输入框不会刷新。放到 `nextTick` 中执行，可以确保这一次赋值触发视图更新，把超长部分真正砍掉。

## 小结

- `maxlength` 在微信小程序端只能当兜底，不能作为唯一的限制手段；
- 输入法组词和粘贴是两个高频触发路径，测试时重点覆盖；
- 手动截断时记得用 `v-model` + `@input` 的受控写法，配合 `nextTick` 回写。
