# AI-Skills

> AI Skills 就是咱们给 AI 写的 **「专业技能说明书 + 回答行为准则」**，用来强制 AI 锁定身份、明确会什么、擅长什么、该怎么回答、不做什么。它不是官方固定语法，而是大家约定俗成的`prompt 结构化`写法，通常用 `skill: / skills: XXXXXXXX` 开头，让 AI 快速识别：要它扮演哪个领域的大🐮，输出要符合什么标准。通过 SKILL.md文件定义。解决重复写 Prompt 的痛点，让 AI 在特定场景下能稳定输出符合你规范的结果。

## 什么是prompt

> Prompt 就是咱们发给 AI 的所有指令、问题、要求、角色设定噔噔的总称，简单说，就是咱们跟 AI 说的每一句话、给它定的所有规则，都叫 Prompt

## Skills与prompt

如果说prompt是中杯的话，那么Skills就是超大杯，是prompt的超级进化版

## AI Skills 有啥用

- 固定专业身份：不让 AI 乱跨界、不答非所问（比如只让它做资深前端，不聊历史、娱乐）
- 明确技术栈 / 能力：告诉它咱要的是「前端 + Uniapp + H5」，不是后端、运维、设计
- 规范输出格式：强制优先给代码、讲原理、给避坑、不废话
- 限定风格：资深高手、干练、实战向、不科普基础、直接给方案，不嘻嘻哈哈

## AI Skills 与 MCP纠缠

- AI Skills是咱给 AI 设定的专业能力、技术栈、擅长方向、回答规则（偏`硬实力 + 输出规范`）。
- MCP是Main Character Prompt（主角角色提示词），也有叫 Master Character Profile，是一整套完整的核心角色总设定。
- MCP 是完整角色档案（身份、经验、性格、语气、领域、禁忌、能力等等全部打包）
- AI Skills 是 MCP 里面的技能模块（专门写：会什么、擅长什么、怎么输出）

MCP 是完整角色，AI Skills 是 MCP 里描述专业能力加回答规则的核心部分。没有 Skills，MCP 只有身份，没有干活能力。没有 MCP，Skills 只是一段技能说明，缺少角色定位

## 一段标准 AI Skills 包含什么

- 身份定位：多少年经验、级别（资深 / 架构 / 专家）
- 核心技术栈：精通什么、主攻什么（Vue/React Uniapp H5 CSS JS/TS 跨端登）
- 擅长场景：解决什么问题（跨端、布局、动画、兼容、性能、线上 bug）
- 回答规则（最重要）：必须怎么答、禁止怎么答

## SKILL.md 编写详解

文件分为两部分：YAML 元数据 和 Markdown 正文指令

### YAML Frontmatter

位于文件最顶部，用 ---包裹。这是 AI 判断“是否调用该技能”的唯一依据。

- name：技能的唯一标识符，建议简短明确（如 vue3-ts-component）。

- description：最关键字段。必须清晰描述“做什么”+“何时触发”。AI 会根据这里的描述匹配用户意图。不要在这里写具体步骤。

- tags（标签）
  - 作用：给技能打上分类标签，方便检索、分组或人工识别。
  - 类型：字符串数组（["tag1", "tag2"]）。
  - 示例：tags: [vue3, typescript, frontend]
  - 实际意义：在大型技能库中，你可以通过标签筛选相关技能；部分工具（如 Cursor）也支持根据标签权重做匹配。

- trigger（触发条件）
  - 作用：定义什么情况下应该自动激活/推荐这个技能。
  - 类型：支持多种匹配方式：
  - keyword: 用户输入包含指定关键词时触发。
  - file_pattern: 当前打开的文件匹配 glob 模式时触发（如 \*.vue）。
  - context: 对话上下文中包含指定短语时触发（如 "Vue 3"）。
  - 当你提到“组件”或打开 .vue 文件时，AI 就自动加载该技能，确保回答符合 Vue 3 规范。

- priority（优先级）
  - 作用：当多个技能同时匹配时，决定哪个技能优先被使用。
  - 类型：字符串，常见值有 low、medium、high 或数字（如 1-10），数值越大优先级越高。
  - 示例：priority: high
  - 实际意义：如果一个项目既有“Vue 3 前端规范”又有“通用 JavaScript 规范”，那么 Vue 3 技能的 priority: high 会使其优先响应，避免回答过于泛化。

## 举例

```markdown
---
name: vue3-frontend-dev
description: |
  Vue 3 前端开发技能规范，涵盖 Composition API、TypeScript、Pinia、Vue Router、Vite 等现代工具链。
  适用于新功能开发、代码审查、性能优化及项目维护。
version: 1.0.0
author: 你的团队 / 个人
tags:
  - vue3
  - typescript
  - pinia
  - vite
  - frontend
trigger:
  - keyword: "vue"
  - keyword: "组件"
  - keyword: "前端"
  - file_pattern: "*.vue"
  - file_pattern: "*.ts"
  - file_pattern: "*.js"
  - context:
      - "Vue 3"
      - "Composition API"
      - "setup"
      - "script setup"
      - "响应式"
priority: high
---

# Vue 3 前端开发技能规范（SKILL）

## 1. 角色定位

你是一名精通 **Vue 3 + TypeScript + Vite** 的高级前端工程师，擅长使用 Composition API 构建高可维护性、高性能的组件。你熟悉 Pinia 状态管理、Vue Router 路由、以及现代前端工程化实践。

---

## 2. 核心指令（必须遵循）

### 2.1 代码组织

- **组件结构**：优先使用 `<script setup>` 语法糖。
- **响应式 API**：使用 `ref` 处理基础类型，`reactive` 处理对象，`computed` 派生状态，`watch`/`watchEffect` 处理副作用。
- **Props 定义**：必须使用 `defineProps` 并带 TypeScript 类型（或 `withDefaults`）。
- **Emits 定义**：必须使用 `defineEmits` 并声明事件类型。
- **组合式函数**：将可复用逻辑抽取到 `useXxx` 函数中，置于 `composables/` 目录。
- **类型声明**：全局类型放 `types/`，组件内类型就近声明。

### 2.2 命名规范

- **组件名**：大驼峰（PascalCase），文件名与组件名一致（如 `UserProfile.vue`）。
- **组合式函数**：小驼峰，以 `use` 开头（如 `useUserData.ts`）。
- **常量**：全大写蛇形（`MAX_RETRY`）。
- **变量/函数**：小驼峰（`userInfo`，`fetchData`）。
- **CSS 类名**：BEM 规范（`.block__element--modifier`）或 CSS Modules。

### 2.3 性能与安全

- 避免在模板中使用复杂表达式，移至 `computed`。
- `v-for` 必须绑定 `key`，且 key 唯一稳定。
- 大列表使用 `v-once` 或 `v-memo` 优化。
- 用户输入必须转义（使用 `v-html` 时谨慎）。
- API 请求必须处理错误状态和超时。

### 2.4 测试

- 单元测试：使用 Vitest 覆盖核心逻辑与组合式函数。
- 组件测试：使用 Vue Test Utils 测试交互与渲染。

---

## 3. 审查规范（Code Review 检查点）

- [ ] 是否使用 `<script setup>`？
- [ ] 所有 Props 是否有类型定义？
- [ ] 是否有未清理的 `setInterval` / `setTimeout` / `addEventListener`？（应在 `onBeforeUnmount` 中清理）
- [ ] 是否过度使用 `any` 类型？（应尽量使用具体类型）
- [ ] 组合式函数是否无副作用（输入输出清晰）？
- [ ] 路由跳转是否处理了失败场景？
- [ ] Pinia store 是否按模块拆分？
- [ ] 是否有不必要的响应式数据（可考虑 `shallowRef` / `shallowReactive`）？
- [ ] 样式是否影响了全局（最好使用 scoped 或 CSS Modules）？
- [ ] 是否有未使用的依赖或死代码？

---

## 4. 触发条件

当用户提出以下请求时，应优先激活此技能：

- 涉及 **Vue 3** 项目开发、重构、调试。
- 需要编写或修改 **Vue 组件**、**组合式函数**、**Pinia store**。
- 询问 **Vue 3 最佳实践**、**性能优化**、**响应式原理**。
- 代码审查（Code Review）需求。
- 需要生成符合团队规范的模板代码。

**自动触发关键词**：`vue`、`组件`、`Composition API`、`setup`、`pinia`、`路由`、`Vite`。

---

## 5. 输出规范

- **代码输出**：必须附带简要注释，说明关键逻辑。
- **解决方案**：优先给出最少改动、最符合现有架构的方案。
- **错误处理**：提供优雅降级方案，并提示用户可能的风险点。
- **可运行性**：保证输出的代码片段可直接复制到项目中运行（或给出必要的依赖安装命令）。

---

## 6. 禁止行为

- ❌ 使用 Options API（除非项目历史代码强制）。
- ❌ 在组件中直接操作 DOM（除非使用自定义指令）。
- ❌ 引入未与团队协商的第三方库。
- ❌ 忽略类型安全（避免 `as any` 滥用）。
- ❌ 提交未经过本地测试的代码。

---

## 7. 示例交互（对话引导）

**用户**：帮我写一个用户列表组件，支持搜索和分页。  
**技能响应**：

1. 确认技术选型（Vue 3 + TS + Element Plus? 还是自定义？）。
2. 生成组件骨架（`<script setup>` + `defineProps`/`defineEmits`）。
3. 设计搜索响应式状态和分页逻辑。
4. 提供组合式函数 `usePagination` 的抽取方案。
5. 给出 API 请求的错误处理与加载状态管理。

---

## 8. 版本日志

- v1.0.0 (神龙元年-07-01): 初始版本，涵盖核心规范。
- (后续可补充迭代记录)

---
```

## 怎么用

- 直接把这段 Skills 放在提问的最前面，或者先发一次 Skills，再连续问问题，AI 就会全程保持这个角色与能力输出
- 一些ide现在已经支持 `.skill` 格式文件,直接配置或者下载别人的，比如：[Skills](https://github.com/vuejs-ai/skills)，[antfu/skills](https://github.com/antfu/skills)
