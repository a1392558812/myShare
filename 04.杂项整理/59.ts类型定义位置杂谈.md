# ts类型定义位置杂谈

## 省流省时间版

- 组件内部私有类型：直接写在 `.vue` / `.ts` 同文件，需要对外就 `export type Xxx`
- 跨页面复用模型：`src/types/xxx.ts`，`export type`，业务代码显式 `import type {}`，溯源清晰
- 只保留一个 `global.d.ts` ，只放：全局变量、扩展Window、declare module 第三方补丁
- 禁止把业务模型（如 User、Order）写进 global.d.ts，极易命名冲突

// 以下是水文章，说的细一些👇

## 判断原则

> 优先：类型跟业务代码放同文件（`.ts`）；只有【全局类型 / 第三方补类型 / 打包库对外声明】才放到 `.d.ts`
> `.d.ts` 不是用来抽离公共业务类型的首选，很多人这里会踩坑。

### 什么时候直接写在当前 `.ts` 文件

// 类型只服务当前模块，或者和当前逻辑强耦合，这里推荐绝大多数场景

- 组件 props、组件返回类型、当前函数入参出参，和这个组件/函数绑定在一起
- 这个类型只在本文件使用，少量地方导入
- 类型会跟着业务逻辑频繁一起修改

eg: `UserList.ts`

```ts
// 和当前组件强绑定，jiu直接写当前文件
type UserItem = {
  id: number;
  name: string;
};
const renderItem = (item: UserItem) => {};
export type { UserItem }; // 需要外部使用就 export type
```

优点：

- 就近阅读，改业务的时候，类型一起改，不容易不同步
- 不需要额外维护 d.ts 文件
- 导入清晰：`import type { UserItem } from './UserList'`，溯源方便

> 公共类型也可以抽成普通 `.ts`（比如 `types/common.ts`），不是必须 d.ts
> `types/common.ts` 写 `export type`

### 什么时候放到 `*.d.ts`

只有下面三类场景才用 d.ts

#### 1：全局类型

// 不用 import，全项目自动识别
比如扩展 `Window`、uniApp全局变量、全局接口、全局命名空间。

> 注：d.ts 里面一旦写 export/import，文件就变成模块，全局失效

```ts
// global.d.ts
interface Window {
  customSdk: any;
}
declare const APP_ENV: string;
```

#### 2：为 JS 库/第三方包补充类型声明

作为类型补丁，第三方库没有自带类型，手写类型描述，`xxx.d.ts`。

```ts
// types/my-lib.d.ts
declare module "my-js-lib" {
  export function doSomething(id: number): void;
}
```

#### 3：打包发布 npm 组件库，自动产出的类型声明

// 不推荐把业务公共类型放到 `xxx.d.ts`
tsconfig 开启 `declaration:true`，构建自动生成 `.d.ts`，**不是手写**，是产物。

注意小坑：

- 全局 d.ts 容易出现类型命名冲突，多人开发易撞interface名字
- 全局类型隐式导入，溯源困难，IDE点不到定义，后期维护很麻fan
- d.ts 不能混业务代码，只能类型；如果以后想加类型工具函数就很别扭

## 项目目录eg

```plaintext
src/
├── types/
│   ├── global.d.ts        ## 【唯一d.ts】全局声明、模块declare
│   ├── common.ts          ## 公共业务类型 export type
│   ├── api.ts             ## 请求相关公共类型 export type
├── pages/
│   └── user/
│       └── index.vue      ## 页面内私有类型写在vue setup里
```

## 补充

如果必须引用别的类型，用 `/// <reference types="./api" />` 三斜线指令。

```typescript
// ✅ global.d.ts
/// <reference types="./api" />

interface Window {
  xxx: string;
}
```

######## tsconfig include 没包含 types 文件夹，d.ts 完全不生效

```typescript
// tsconfig.json
{
  "include": [
    "src/**/*.ts",
    "src/**/*.d.ts", // 一定要包含d.ts
    "src/**/*.vue"
  ]
}
```
