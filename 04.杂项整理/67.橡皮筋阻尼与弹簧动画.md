# 橡皮筋越界阻尼与弹簧动画

是什么：比如滚动列表拖到顶了，手指还在往上划，内容跟着走，但越走越沉，松手后顺着速度滑回去，就是那种iOS的手感，它由两个独立的模块拼成：**越界时的位移映射**（橡皮筋阻尼）和**回位时的时序曲线**（弹簧动画）。

---

## 数学与手感

这个功能就是手指动了`dx`，内容应该动多少`dy`，即`f(x)`映射一个y，正常滚动时 `dy/dx = 1`。到了边界，这个比值必须变。人感知的不是位移本身，而是这个比值的变化过程，数学公式：`dy = dx·D·c/(D + c·abs(dx))`，效果即起步跟手、越拖越沉、永远拉不到底,此时的约束很清楚：(回到高中数学‘求导’)

### 滑动时阻尼拖拽

// `x` 是越界量（带符号），`D` 是参考尺寸，`c` 是阻尼常数。

1. `f(0) = c`，第一像素跟手比例就是 `c = 0.55`，不快不慢，且连续过渡到 1:1 滚动。
2. `f'(x)` 在 `|x|`上连续且严格递减
3. **有上界**：`lim f(±∞) = ±D`。理论极限是 `D`，永远到不了。

### 手势接管与反函数

// `f⁻¹(y) = y · D / (c · (D - |y|))`
当当动画停在某个被压缩的呈现位置上时，,用户按住手指要接着拖时，需要知道"这个呈现位置对应多少原始位移"，才能让 `raw` 继续累加而不跳变。

// 我的实现里用了个省事的办法绕开它

```ts
export const rubberBandInverse = (
  banded: number,
  config: RubberBandConfig,
): number => {
  const { constant, dimension } = config;
  const sign = banded < 0 ? -1 : 1;
  // y 永远到不了 D，留一点余量避免除零
  const distance = Math.min(Math.abs(banded), dimension * 0.995);
  return (sign * dimension * distance) / (constant * (dimension - distance));
};
```

### `D`取什么

**取容器在该轴上的可视长度**（`clientHeight`）。因为上界`D` 的物理含义是"最多能露出多少空白"，这是以视口为尺度的概念。

如果误取内容高度，长列表会有灾难性表现：`D = 10000`时，手指拖400px得到`215px`，瞬时跟手比还有 `0.53`，和起步的 `0.55` 几乎没有区别，等于全程没有变硬，阻尼形同虚设。对照 `D = 800` 的 `0.338`，差距一目了然。`D` 越大，压缩越弱，这是公式的直接推论。

## 弹簧为什么不用缓动曲线

回位动画，第一反应是 `transition: transform 0.4s cubic-bezier(...)`。三个理由说明它不行：

### 1. 无法继承速度

用户松手那一刻速度可能是 1200px/s，方向朝外。缓动曲线是从 0 速度起步的，动画的头几帧就要把"1200px/s 的外向运动"强行反转成"内向运动"，视觉上是一次急刹车，正确做法是把松手速度作为弹簧的**初始条件**，让位移先继续往外冲一点再回来，需要用到一个公式：**欠阻尼二阶弹簧系统解析解**

// 公式不用记，也不用理解，如果真的要用，现场网上搜就行，我们只用知道这个公式套进去就能出结果，`f(x) = y` 这个黑盒不耽误我们开发，

```
x(t) = 目标 + e^(-ζωt) · [(x₀-目标)·cos(ω_d t) + ((v₀ + ζω(x₀-目标))/ω_d)·sin(ω_d t)]
```

| 符号                                | 含义                                                                                                                                                        |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| $t$                                 | 时间，单位 s；从松手那一刻开始计时 $(t=0)$                                                                                                                  |
| $(x(t))$                            | t 时刻物体位置（我们动画里要实时渲染的值，比如 transform 偏移量）                                                                                           |
| $x_{target}$                        | 弹簧静止平衡位置（松手后最终要回到的目标位置）                                                                                                              |
| $x_0$                               | **初始位置**：松手瞬间的位置                                                                                                                                |
| $v_0$                               | **初始速度**：松手瞬间的瞬时速度（px/s，可正可负；向外为正）                                                                                                |
| $\zeta$ zeta                        | **阻尼比** 核心参数 $\zeta<1$：欠阻尼（会回弹超调，就是我们想要的弹簧效果） $\zeta=1$：临界阻尼，最快回到目标不震荡 $\zeta>1$：过阻尼，慢悠悠挪回去，不会弹 |
| $\omega$ omega                      | **无阻尼固有角频率**，单位 rad/s $\omega = \sqrt{\dfrac{k}{m}}$，k劲度系数，m质量；越大弹簧越硬、回弹越快                                                   |
| $\omega_d$ omega_d                  | **阻尼固有角频率**（带阻尼后的实际震荡频率） $$\omega_d = \omega\sqrt{1-\zeta^2}$$                                                                          |
| $e^{-\zeta\omega t}$                | 衰减包络项。指数衰减，控制振幅慢慢变小；阻尼越大，衰减越快                                                                                                  |
| $\cos(\omega_d t),\sin(\omega_d t)$ | 震荡周期项，负责来回摆动                                                                                                                                    |

当 \(t=0\) 代入验算：
\(\cos0=1,\sin0=0\)
\(x(0)=x*{target}+(x_0-x*{target}) = x_0\)

对公式求导得到 \(v(t)\)，\(t=0\) 时刚好等于 \(v_0\)。这就是它能**承接松手瞬时速度**的根本：解本身就把 \(v_0\) 作为初始条件。

### 2. 无法中断

手指再次按下时，缓动曲线只能"从当前位置重新开一条新曲线"，新曲线初速为 0，这又是一次急停。可打断的动画必须能读出"当前值 + 当前速度"，并用它们作为下一段动画的初值。

### 3. 时长是假的

弹簧的时长由距离和初速共同决定：拖20px回弹可能是0.15s，甩800px回弹要 0.6s。固定 `duration` 的曲线要么短距离拖沓，要么长距离仓促。

### 能交给CSS吗

`linear()`缓动能用采样点近似弹簧曲线，视觉上很像。但它依然无法继承初速、无法在中途接管，只要手势是JS驱动的，动画就必须也由JS驱动，否则一次触摸就会暴露。

浏览器原生的 `overscroll-behavior: contain` 只能**关掉**系统的橡皮筋，不能自定义。想要自定义手感，只能自己算。

### 方程

```
m·x'' + c·x' + k·x = 0
```

三个参数：质量 `m`、刚度 `k`、阻尼 `c`。但这套参数不直观 —— `k = 100` 到底快不快？得先知道 `m`。

工程上更好用的是**响应周期 + 阻尼比**这套参数化（SwiftUI 的 `response` / `bounce`、Framer Motion 的 `stiffness` / `damping`，本质都是翻译）：

```
ω = 2π / response          角频率
ζ = dampingRatio           阻尼比
k = ω²·m
c = 2·ζ·ω·m
```

`response` 直接就是"这个弹簧大概多久走完一个周期"，`ζ` 决定"弹不弹"。两个维度各自独立，调参时不会互相打架。

`ζ` 与超调量的关系：

| `ζ`  | 超调比例 | 观感               |
| ---- | -------- | ------------------ |
| 0.4  | 25.4%    | 弹得很夸张，玩具感 |
| 0.5  | 16.3%    | 明显回弹           |
| 0.6  | 9.5%     | 轻快               |
| 0.72 | 3.8%     | 克制               |
| 0.8  | 1.5%     | 几乎看不出回弹     |
| 1.0  | 0        | 临界，最快不超调   |
| > 1  | 0        | 过阻尼，慢慢爬回去 |

超调比例有闭式解 `e^(-πζ/√(1-ζ²))`，上表就是它算出来的。列表越界回弹用 0.6 ~ 0.8，抽屉/弹窗用 0.75 ~ 0.9，需要"沉稳"的界面直接给 1。

## 为什么用解析解，而不是逐帧积分

逐帧积分的做法：每帧 `dt`，用 `v += a·dt; x += v·dt` 递推。看起来简单，坑很深。

**显式 Euler 会炸。** 对 `x'' = -ω²x`，递推的稳定条件是 `ω·dt < 2`。取 `response = 0.42s`，`ω ≈ 15`，60fps 下 `ω·dt ≈ 0.25`，安全。但真实设备会掉帧：后台切回、GC、复杂布局，某一帧 `dt` 到了 200ms，`ω·dt = 3`，直接发散 —— 内容飞出屏幕。

**半隐式 Euler 只是不发散**，轨迹依然依赖 `dt`。同一段动画在 60Hz 和 120Hz 上走出来的曲线不一样，要准确必须内部 `substep`，把 `dt` 压到 `1/240s` 以下，浪费 CPU。

**解析解没有这些问题。** 给定初值和时间 `t`，直接算出 `x(t)` 和 `v(t)`：

- 帧率无关：60Hz、120Hz、掉一帧，同一条曲线；
- 零累积误差；
- 可任意 seek：可以随时问"第 0.37 秒时它在哪里"，这在调试回放、倒带、时间轴 scrub 时是刚需；
- 边界天然正确：`t=0` 时精确等于初值。

代价是要按三种阻尼区间分别推导闭式解。代码不长：

```ts
export const createSpringSolver = (
  from: number,
  to: number,
  velocity: number,
  config: Pick<SpringConfig, "response" | "dampingRatio">,
): SpringSolver => {
  const omega = (2 * Math.PI) / Math.max(config.response, 1e-4);
  const zeta = Math.max(config.dampingRatio, 0);
  const delta = from - to;

  // 欠阻尼：一对共轭复根，振荡衰减
  if (zeta < 1) {
    const omegaD = omega * Math.sqrt(1 - zeta * zeta);
    const decay = zeta * omega;
    const a = delta;
    const b = (velocity + decay * delta) / omegaD;

    return (time) => {
      const exp = Math.exp(-decay * time);
      const cos = Math.cos(omegaD * time);
      const sin = Math.sin(omegaD * time);
      return {
        value: to + exp * (a * cos + b * sin),
        velocity:
          exp *
          ((b * omegaD - decay * a) * cos - (a * omegaD + decay * b) * sin),
      };
    };
  }

  // 过阻尼：两个不相等的实根，纯指数收敛，绝不越过目标
  if (zeta > 1) {
    const spread = omega * Math.sqrt(zeta * zeta - 1);
    const rootA = -zeta * omega + spread;
    const rootB = -zeta * omega - spread;
    const coefA = (velocity - rootB * delta) / (rootA - rootB);
    const coefB = (rootA * delta - velocity) / (rootA - rootB);

    return (time) => {
      const expA = Math.exp(rootA * time);
      const expB = Math.exp(rootB * time);
      return {
        value: to + coefA * expA + coefB * expB,
        velocity: rootA * coefA * expA + rootB * coefB * expB,
      };
    };
  }

  // 临界阻尼：重根，速度单调趋零
  const a = delta;
  const b = velocity + omega * delta;

  return (time) => {
    const exp = Math.exp(-omega * time);
    return {
      value: to + (a + b * time) * exp,
      velocity: (b - omega * (a + b * time)) * exp,
    };
  };
};
```

实测最大位移偏差 `1.60e-10`、最大速度偏差 `1.56e-9`，边界条件 `t=0` 精确复位到 `(from, v₀)`，

### 停下来的判据

`|x - 目标| < ε && |v| < ε`，两个条件都要，只看速度的话会翻车，欠阻尼弹簧的速度一定会穿过零点，速度为零的那一刻位移可能还差一大截；只看位移则会因为渐近逼近而永远等不到。

## 把手势和弹簧接起来

我见到的实现里，最常见的写法是"拖动时直接改呈现值，松手后从呈现值开始弹"。这样做的问题在于：手指回拉时，压缩映射是单向的，你不知道该还原多少。我的做法是维护一个**不压缩的原始位移 `raw`**：

- 手指的每一次 `pointermove` 都直接累加到 `raw`；
- 渲染时才对 `raw` 施加橡皮筋映射，得到 `display`；
- 弹簧永远跑在 `raw` 空间上。

```ts
/** 原始滚动位置：可以 < 0，也可以 > maxScroll，这是"越界量"的唯一真相 */
const position = ref(0);
const maxScroll = ref(0);
const viewportSize = ref(1);

const display = computed(() =>
  rubberBandClamp(position.value, 0, maxScroll.value, {
    constant: 0.55,
    dimension: viewportSize.value,
  }),
);

const translateY = computed(() => -display.value);
```

`rubberBandClamp` 就是三段分支：界内原样、低于 `min` 的部分压进橡皮筋、高于 `max` 的部分压进橡皮筋,好处是路径天然可逆,`f`严格单调，往回拖 100px就走回100px的原始量，呈现位置自然回到原处，不需要每帧调反函数,手指接管时也不用换算,`raw`本来就一直在。

### 速度估计

松手速度不能取最后两帧的差。单帧抖动（尤其是 120Hz 下只隔 8ms）会被放大十几倍，判断成一次疯狂甩动。取最近 100ms 窗口的首尾差：

```ts
const samples: Array<{ time: number; value: number }> = [];
const prune = (window: number): void => {
  const time = performance.now();
  // 至少留一个样本，避免窗口内全是旧数据时数组清空
  while (samples.length > 1 && time - samples[0].time > window) samples.shift();
};

const pushSample = (value: number): void => {
  samples.push({ time: performance.now(), value });
  prune(100);
};

const readVelocity = (): number => {
  prune(100); // 必须在读之前再裁一次，否则停手松手会用到陈旧样本
  if (samples.length < 2) return 0;
  const first = samples[0];
  const last = samples[samples.length - 1];
  const seconds = (last.time - first.time) / 1000;
  if (seconds <= 0) return 0;
  return clamp((last.value - first.value) / seconds, -4000, 4000);
};
```

`prune`有两个作用：一是限制窗口长度，二是手指停住再松手时，窗口里只剩一个样本，速度自然是 0。这解决了一个很烦的bug，拖完停200ms再松手，不该触发惯性，但注意`pushSample` 里那次 `prune` 只是打扫房间，真正决定结果的必须在 `readVelocity` 里再裁一次：`pointerup` 可能发生在最后一次 `pointermove` 几百毫秒之后，那一刻窗口里全是旧样本。

另外两个细节：

- 时间基准用 `performance.now()`，不用 `event.timeStamp`。后者在部分浏览器上是相对页面加载的，且在 `requestAnimationFrame` 里不可比。
- 速度必须截断上限（`±4000px/s`）。触控板、多指、设备时钟抖动都能制造出异常值，一个异常值就能把内容甩飞。

### 惯性用"投影 + 弹簧"表达

真实的惯性需要单独的指数衰减阶段，然后在边界处交接。为了保持"只有一个动画原语"的简洁性，我用了一个近似：

```ts
const speed = readVelocity();
const projected =
  Math.abs(speed) < 40 ? position.value : position.value + speed * 0.3;
const target = clamp(projected, 0, maxScroll.value);
void animateTo(target, speed);
```

把速度投影成一段距离（`0.3` 秒的行程），夹到合法区间，然后用**同一个弹簧**吃掉它。松手速度越大，弹簧的目标越远，动画越长。

这个近似的代价是长距离滑行不够"飘"——真惯性会滑得更远更匀。收益是状态机里没有第二种动画，中断、接管、越界回弹全部复用同一套逻辑。如果你要 iOS 那种长距离甩动，做法是加一个指数衰减阶段：`x(t) = x₀ + (v₀/λ)(1 - e^(-λt))`，`λ ≈ 2/s`，解析求它撞到边界的时刻，把那一刻的位置和速度作为弹簧初值交接 —— 这就是"三阶段"模型，代码会多一个状态，但物理更忠实。

### 中断

```ts
let pointerId: number | null = null;
let startPointerY = 0;
let startPosition = 0;

const onPointerDown = (event: PointerEvent): void => {
  if (pointerId !== null || event.button !== 0) return;
  const element = event.currentTarget;
  if (!(element instanceof HTMLElement)) return;

  generation += 1;
  spring.stop();
  dragging.value = true;
  settling.value = false;
  pointerId = event.pointerId;
  startPointerY = event.clientY;
  startPosition = position.value;
  samples.length = 0;
  pushSample(position.value);
  element.setPointerCapture(event.pointerId);
};
```

`spring.stop()` 让动画就地停住，当前值保留在 `position`里、当前速度保留在`velocity` 里。下一段动画从这里接着算，视觉上没有断层，`generation` 是给promise用的。`stop()` 会把悬挂的 promise `resolve` 掉，如果用户的回调里有"滚动结束→上报曝光"这类逻辑，必须能区分"真的结束了"和"被打断了"：

```ts
const id = generation;
spring.to(target, speed).then((final) => {
  if (id !== generation) return; // 过期回调，丢弃
  // 用「离目标还有多远」区分真正走完和被手势打断
});
```

## 完整代码

### `types.ts`

```ts
/** 一条列表数据。 */
export type ListItem = {
  readonly id: number;
  readonly title: string;
  readonly summary: string;
};

/**
 * 弹簧参数。
 *
 * 不用 k / c / m，而用「响应周期 + 阻尼比」：两个维度独立，调参不打架。
 * response 的物理含义是「走完一个完整振荡周期大约多久」（秒）。
 */
export type SpringConfig = {
  /** 角周期：ω = 2π / response */
  readonly response: number;
  /** 阻尼比 ζ：<1 欠阻尼、=1 临界、>1 过阻尼 */
  readonly dampingRatio: number;
  /** 位移收敛阈值（px），停下判据的一半 */
  readonly restDelta: number;
  /** 速度收敛阈值（px/s），停下判据的另一半 */
  readonly restSpeed: number;
};

/**
 * 解析解在 t 时刻的完整状态。
 *
 * velocity 是 value 对时间的真实一阶导数，不是差分近似 —— 它可以直接
 * 当成下一段动画的初速度喂回去，这是「可中断」的基础。
 */
export type SpringState = {
  readonly value: number;
  readonly velocity: number;
};
```

### `rubberBand.ts`

```ts
export type RubberBandConfig = {
  /** 阻尼常数：1 表示完全不阻尼，iOS 实测值约 0.55 */
  readonly constant: number;
  /** 参考尺寸，必须取容器在该轴上的**可视长度**（clientHeight），不是内容高度 */
  readonly dimension: number;
};

/** 轴开关：控制顶部 / 底部越界阻尼是否生效 */
export type RubberBandAxisOptions = {
  /** 顶部越界是否允许，默认 true */
  readonly top?: boolean;
  /** 底部越界是否允许，默认 true */
  readonly bottom?: boolean;
};

/** 把"手指走了多少"映射成"内容该走多少" */
export const rubberBand = (
  offset: number,
  config: RubberBandConfig,
): number => {
  const { constant, dimension } = config;
  const distance = Math.abs(offset);
  if (distance === 0) return 0;
  if (dimension <= 0) return 0;
  const sign = offset < 0 ? -1 : 1;
  return (
    (sign * distance * dimension * constant) / (dimension + constant * distance)
  );
};

/** f'(x) = c·D² / (D + c|x|)²，用于把 display 速度换算回 raw 速度 */
export const rubberBandDerivative = (
  offset: number,
  config: RubberBandConfig,
): number => {
  const { constant, dimension } = config;
  const base = dimension + constant * Math.abs(offset);
  return (constant * dimension * dimension) / (base * base);
};

/**
 * 反函数 f⁻¹(y) = y·D / (c·(D - |y|))。
 * 本方案里用不到它（raw 一直留在手里），但「只持有 display 值」的场景必须靠它。
 */
export const rubberBandInverse = (
  banded: number,
  config: RubberBandConfig,
): number => {
  const { constant, dimension } = config;
  const sign = banded < 0 ? -1 : 1;
  // y 永远到不了 D，留 0.5% 余量避免除零
  const distance = Math.min(Math.abs(banded), dimension * 0.995);
  return (sign * dimension * distance) / (constant * (dimension - distance));
};

/**
 * 双端越界的完整映射：
 * 落在 [min, max] 内的位移 1:1 呈现，越界的部分压进橡皮筋。
 *
 * axis 控制哪一端允许越界：关闭的那一端会被硬钳制在边界上。
 * 默认两端都开启，与旧调用保持兼容。
 */
export const rubberBandClamp = (
  offset: number,
  min: number,
  max: number,
  config: RubberBandConfig,
  axis: RubberBandAxisOptions = {},
): number => {
  const { top = true, bottom = true } = axis;
  if (offset < min) {
    return top ? min + rubberBand(offset - min, config) : min;
  }
  if (offset > max) {
    return bottom ? max + rubberBand(offset - max, config) : max;
  }
  return offset;
};
```

### `spring.ts`

```ts
import type { SpringConfig, SpringState } from "./types";

/** 建议默认值：0.42s 一个周期、ζ = 0.72，只冒 3.8% 的头 */
export const DEFAULT_SPRING: SpringConfig = {
  response: 0.42,
  dampingRatio: 0.72,
  restDelta: 0.5,
  restSpeed: 0.5,
};

/** 求解器的签名：时间 → 状态。可任意调用、可回放、可 scrub。 */
export type SpringSolver = (time: number) => SpringState;

/**
 * 三分支解析解：欠阻尼 / 临界 / 过阻尼。
 *
 * 给定 from / to / velocity / config，返回一个 t → state 的纯函数。
 * 帧率无关、零累积误差、可任意 seek、t=0 精确等于初值。
 */
export const createSpringSolver = (
  from: number,
  to: number,
  velocity: number,
  config: Pick<SpringConfig, "response" | "dampingRatio">,
): SpringSolver => {
  const omega = (2 * Math.PI) / Math.max(config.response, 1e-4);
  const zeta = Math.max(config.dampingRatio, 0);
  const delta = from - to;

  // 欠阻尼：一对共轭复根，振荡衰减
  if (zeta < 1) {
    const omegaD = omega * Math.sqrt(1 - zeta * zeta);
    const decay = zeta * omega;
    const a = delta;
    const b = (velocity + decay * delta) / omegaD;

    return (time) => {
      const exp = Math.exp(-decay * time);
      const cos = Math.cos(omegaD * time);
      const sin = Math.sin(omegaD * time);
      return {
        value: to + exp * (a * cos + b * sin),
        velocity:
          exp *
          ((b * omegaD - decay * a) * cos - (a * omegaD + decay * b) * sin),
      };
    };
  }

  // 过阻尼：两个不相等的实根，纯指数收敛，绝不越过目标
  if (zeta > 1) {
    const spread = omega * Math.sqrt(zeta * zeta - 1);
    const rootA = -zeta * omega + spread;
    const rootB = -zeta * omega - spread;
    const coefA = (velocity - rootB * delta) / (rootA - rootB);
    const coefB = (rootA * delta - velocity) / (rootA - rootB);

    return (time) => {
      const expA = Math.exp(rootA * time);
      const expB = Math.exp(rootB * time);
      return {
        value: to + coefA * expA + coefB * expB,
        velocity: rootA * coefA * expA + rootB * coefB * expB,
      };
    };
  }

  // 临界阻尼：重根，速度单调趋零
  const a = delta;
  const b = velocity + omega * delta;

  return (time) => {
    const exp = Math.exp(-omega * time);
    return {
      value: to + (a + b * time) * exp,
      velocity: (b - omega * (a + b * time)) * exp,
    };
  };
};

/** 对外暴露的弹簧句柄：值 + 速度 + 目标 + 控制方法 + 订阅 */
export type SpringValue = {
  readonly value: number;
  readonly velocity: number;
  readonly target: number;
  readonly isAnimating: boolean;
  /** 去掉返回 promise，动画结束或被 stop() 打断时 resolve 成「最终落点」 */
  readonly to: (
    target: number,
    initialVelocity?: number,
    overrides?: Partial<SpringConfig>,
  ) => Promise<number>;
  /** 直接把值和目标钉到某个位置，不播动画 */
  readonly set: (value: number) => void;
  /** 就地停住：保留当前值和当前速度，供下一段动画接着算 */
  readonly stop: () => void;
  readonly onChange: (
    listener: (value: number, velocity: number) => void,
  ) => () => void;
};

/**
 * rAF 驱动 + promise 封装。
 *
 * overrides 传函数而不是对象：每次 to() 都重读一遍最新参数，
 * 配合 Vue 的响应式 props，拖动滑杆时手感实时变化，不必重建实例。
 */
export const createSpringValue = (
  initial: number,
  overrides: () => Partial<SpringConfig> = () => ({}),
): SpringValue => {
  const listeners = new Set<(value: number, velocity: number) => void>();

  let value = initial;
  let velocity = 0;
  let target = initial;
  let config: SpringConfig = { ...DEFAULT_SPRING, ...overrides() };
  let solver: SpringSolver | null = null;
  let startedAt = 0;
  let frame: number | null = null;
  let pending: ((value: number) => void) | null = null;

  const emit = (): void => {
    listeners.forEach((listener) => listener(value, velocity));
  };

  const halt = (finalValue: number): void => {
    value = finalValue;
    velocity = 0;
    solver = null;
    if (frame !== null) {
      cancelAnimationFrame(frame);
      frame = null;
    }
    const resolve = pending;
    pending = null;
    emit();
    resolve?.(finalValue);
  };

  const step = (now: number): void => {
    if (!solver) return;
    // 用 elapsed 而不是累积 dt：掉帧、倍速、后台唤醒都不会让轨迹失真。
    // rAF 首帧时间戳可能略早于 startedAt，所以兜一个 0。
    const elapsed = Math.max((now - startedAt) / 1000, 0);
    const state = solver(elapsed);
    value = state.value;
    velocity = state.velocity;

    // 位移和速度都收敛才算停：只看速度会在过零点误判
    const settled =
      Math.abs(value - target) <= config.restDelta &&
      Math.abs(velocity) <= config.restSpeed;

    if (settled) {
      halt(target);
      return;
    }
    emit();
    frame = requestAnimationFrame(step);
  };

  const stop = (): void => {
    if (solver === null && frame === null) return;
    halt(value);
  };

  const set = (next: number): void => {
    stop();
    target = next;
    value = next;
    velocity = 0;
    emit();
  };

  const to = (
    nextTarget: number,
    initialVelocity = 0,
    callOverrides?: Partial<SpringConfig>,
  ): Promise<number> => {
    stop();
    config = { ...DEFAULT_SPRING, ...overrides(), ...(callOverrides ?? {}) };
    target = nextTarget;
    velocity = initialVelocity;

    const alreadyThere =
      Math.abs(value - nextTarget) <= config.restDelta &&
      Math.abs(initialVelocity) <= config.restSpeed;

    if (alreadyThere) {
      halt(nextTarget);
      return Promise.resolve(nextTarget);
    }

    solver = createSpringSolver(value, nextTarget, initialVelocity, config);
    startedAt = performance.now();
    frame = requestAnimationFrame(step);

    return new Promise<number>((resolve) => {
      pending = resolve;
    });
  };

  const onChange = (
    listener: (value: number, velocity: number) => void,
  ): (() => void) => {
    listeners.add(listener);
    return () => {
      listeners.delete(listener);
    };
  };

  return {
    get value() {
      return value;
    },
    get velocity() {
      return velocity;
    },
    get target() {
      return target;
    },
    get isAnimating() {
      return solver !== null;
    },
    to,
    set,
    stop,
    onChange,
  };
};
```

几个注意点：

- `overrides`传了函数，这样每次`to()`都会重新读一遍最新参数，配合 Vue 的响应式 props，拖动滑杆时手感实时变化，不需要重建实例。
- `step` 里用 `elapsed` 而不是 `dt`,只要记住起始时间戳，任何时候算出 `(now - startedAt)/1000` 就能定位到曲线上的点，掉帧不影响结果。
- `halt()`顺手resolve。中断不是"取消"，调用方有权知道结束时的值，所以用 `resolve` 而不是 `reject`，并用`generation`在调用方区分。

### `useRubberBandScroll.ts`

手势状态机，这是整个方案里唯一有"状态"的地方

```ts
import { computed, onScopeDispose, ref, watch } from "vue";
import type { ComputedRef, Ref } from "vue";
import { rubberBandClamp } from "./rubberBand";
import { createSpringValue } from "./spring";
import type { SpringConfig } from "./types";

/** 越界 / 惯性相关的可调项，全部可省略，省略则用默认值。 */
export type RubberBandScrollOptions = {
  /** 橡皮筋阻尼常数，等于起步跟手比例 f'(0)，甜区 0.45 ~ 0.65 */
  constant?: number;
  /** 惯性投影时长（秒）：把松手速度投影成一段距离 */
  projection?: number;
  /** 低于该速度不投影，直接回弹（px/s） */
  minFlingVelocity?: number;
  /** 速度上限（px/s）：触控板、多指、时钟抖动都能给出异常值 */
  maxVelocity?: number;
  /** 速度采样窗口（毫秒）：取窗口首尾差，别用最后两帧 */
  sampleWindow?: number;
  /** 弹簧参数，每次 to() 时重读，拖动滑杆可实时改手感 */
  spring?: Partial<SpringConfig>;
  /** 界内 1:1 滚动开关，默认 true。关闭后手势被忽略，但 scrollTo() 仍可用 */
  scrollable?: boolean;
  /** 顶部越界阻尼开关，默认 true。关闭后 raw 被硬钳制在 0 */
  overScrollTop?: boolean;
  /** 底部越界阻尼开关，默认 true。关闭后 raw 被硬钳制在 maxScroll */
  overScrollBottom?: boolean;
};

type ResolvedOptions = Required<Omit<RubberBandScrollOptions, "spring">> & {
  spring: Partial<SpringConfig>;
};

/** 组件里实际会用到的一切，包括模板事件绑定和 defineExpose 的成员。 */
export type RubberBandScrollApi = {
  readonly position: Ref<number>;
  readonly velocity: Ref<number>;
  readonly maxScroll: Ref<number>;
  readonly viewportSize: Ref<number>;
  readonly display: ComputedRef<number>;
  readonly translateY: ComputedRef<number>;
  readonly dragging: Ref<boolean>;
  readonly settling: Ref<boolean>;
  readonly onPointerDown: (event: PointerEvent) => void;
  readonly onPointerMove: (event: PointerEvent) => void;
  readonly onPointerUp: (event: PointerEvent) => void;
  readonly onPointerCancel: (event: PointerEvent) => void;
  /** 程序化滚动，返回本次动画的最终落点（被打断时就是打断处的值） */
  readonly scrollTo: (
    target: number,
    initialVelocity?: number,
    overrides?: Partial<SpringConfig>,
  ) => Promise<number>;
  /** 重新量一次容器与内容尺寸 */
  readonly measure: () => void;
};

const DEFAULTS: ResolvedOptions = {
  constant: 0.55,
  projection: 0.3,
  minFlingVelocity: 40,
  maxVelocity: 4000,
  sampleWindow: 100,
  spring: {},
  scrollable: true,
  overScrollTop: true,
  overScrollBottom: true,
};

const clamp = (value: number, min: number, max: number): number =>
  Math.min(Math.max(value, min), max);

export const useRubberBandScroll = (
  viewportRef: Ref<HTMLElement | null>,
  contentRef: Ref<HTMLElement | null>,
  readOptions: () => RubberBandScrollOptions = () => ({}),
): RubberBandScrollApi => {
  const resolveOptions = (): ResolvedOptions => {
    const raw = readOptions();
    return {
      constant: raw.constant ?? DEFAULTS.constant,
      projection: raw.projection ?? DEFAULTS.projection,
      minFlingVelocity: raw.minFlingVelocity ?? DEFAULTS.minFlingVelocity,
      maxVelocity: raw.maxVelocity ?? DEFAULTS.maxVelocity,
      sampleWindow: raw.sampleWindow ?? DEFAULTS.sampleWindow,
      spring: raw.spring ?? DEFAULTS.spring,
      scrollable: raw.scrollable ?? DEFAULTS.scrollable,
      overScrollTop: raw.overScrollTop ?? DEFAULTS.overScrollTop,
      overScrollBottom: raw.overScrollBottom ?? DEFAULTS.overScrollBottom,
    };
  };

  // 注意：overrides 传的是函数，所以这里必须已经定义好 resolveOptions
  const spring = createSpringValue(0, () => resolveOptions().spring);

  /** 原始滚动位置：可以 < 0，也可以 > maxScroll，这是「越界量」的唯一真相 */
  const position = ref(0);
  const velocity = ref(0);
  const maxScroll = ref(0);
  const viewportSize = ref(1);
  const dragging = ref(false);
  const settling = ref(false);

  /** 自增版本号：用来丢弃被打断的过期 promise 回调 */
  let generation = 0;

  const unsubscribe = spring.onChange((value, speed) => {
    position.value = value;
    velocity.value = speed;
  });

  const display = computed(() => {
    const opts = resolveOptions();
    return rubberBandClamp(
      position.value,
      0,
      maxScroll.value,
      { constant: opts.constant, dimension: viewportSize.value },
      { top: opts.overScrollTop, bottom: opts.overScrollBottom },
    );
  });

  const translateY = computed(() => -display.value);

  /* ---------------- 速度采样 ---------------- */

  const samples: Array<{ time: number; value: number }> = [];

  /**
   * 裁剪窗口。两个作用：限制窗口长度；以及手指停住再松手时窗口里只剩
   * 一个样本，速度自然为 0 —— 这解决了「拖完停 200ms 再松手还触发惯性」。
   */
  const prune = (window: number): void => {
    const time = performance.now();
    // 至少留一个样本，避免窗口内全是旧数据时数组清空
    while (samples.length > 1 && time - samples[0].time > window)
      samples.shift();
  };

  const pushSample = (value: number): void => {
    samples.push({ time: performance.now(), value });
    prune(resolveOptions().sampleWindow);
  };

  /** 最近窗口的首尾差估速：单帧差在 120Hz 下会被放大十几倍 */
  const readVelocity = (): number => {
    const { sampleWindow, maxVelocity } = resolveOptions();
    prune(sampleWindow); // 必须在读之前再裁一次，否则停手松手会用到陈旧样本
    if (samples.length < 2) return 0;
    const first = samples[0];
    const last = samples[samples.length - 1];
    const seconds = (last.time - first.time) / 1000;
    if (seconds <= 0) return 0;
    const speed = (last.value - first.value) / seconds;
    return clamp(speed, -maxVelocity, maxVelocity);
  };

  /* ---------------- 测量 ---------------- */

  const measure = (): void => {
    const viewport = viewportRef.value;
    const content = contentRef.value;
    if (!viewport || !content) return;
    viewportSize.value = Math.max(viewport.clientHeight, 1);
    maxScroll.value = Math.max(content.offsetHeight - viewportSize.value, 0);
    if (dragging.value) return;
    // 内容被改短时把位置收回合法区间，否则下次拖动会先看到一段空白
    const next = clamp(position.value, 0, maxScroll.value);
    if (next !== position.value) spring.set(next);
  };

  /* ---------------- 动画 ---------------- */

  const animateTo = (
    target: number,
    initialVelocity = 0,
    overrides?: Partial<SpringConfig>,
  ): Promise<number> => {
    generation += 1;
    const id = generation;
    const nextTarget = clamp(target, 0, maxScroll.value);
    settling.value = true;
    return spring.to(nextTarget, initialVelocity, overrides).then((final) => {
      // 被打断时回调会晚到，别让它把新动画的状态误置为 false
      if (id !== generation) return final;
      position.value = final;
      settling.value = false;
      return final;
    });
  };

  const scrollTo = (
    target: number,
    initialVelocity = 0,
    overrides?: Partial<SpringConfig>,
  ): Promise<number> => animateTo(target, initialVelocity, overrides);

  /* ---------------- 手势 ---------------- */

  let pointerId: number | null = null;
  let startPointerY = 0;
  let startPosition = 0;

  const onPointerDown = (event: PointerEvent): void => {
    if (pointerId !== null || event.button !== 0) return;
    const element = event.currentTarget;
    if (!(element instanceof HTMLElement)) return;
    const opts = resolveOptions();

    generation += 1;
    // 任何按下都先停住正在跑的动画（程序化 scrollTo 也要能被手指打断）
    spring.stop();
    settling.value = false;

    // 正常滚动关闭：不进入拖动状态，pointerId 保持 null，
    // 后续 pointermove / pointerup 会因为 event.pointerId !== pointerId 直接 return。
    // 但若当前处于越界位置（例如上一段 scrollTo 未完成、或开关刚切换），
    // 让弹簧把它收回合法区间，而不是停在空白里。
    if (!opts.scrollable) {
      const next = clamp(position.value, 0, maxScroll.value);
      if (next !== position.value) void animateTo(next, 0);
      return;
    }

    dragging.value = true;
    pointerId = event.pointerId;
    startPointerY = event.clientY;
    startPosition = position.value;
    samples.length = 0;
    pushSample(position.value);
    // 手指移出元素后事件仍送到它身上，松手自动释放
    element.setPointerCapture(event.pointerId);
  };

  const onPointerMove = (event: PointerEvent): void => {
    if (event.pointerId !== pointerId) return;
    const opts = resolveOptions();
    if (!opts.scrollable) return; // 双保险（pointerId 已挡住，这里更清晰）

    // 手指上移 => 内容上移 => position 增大，所以是减法
    let next = startPosition - (event.clientY - startPointerY);

    // 关键：越界开关关闭时，直接在 raw 上钳死。
    // 这样 readVelocity() 在边界处读到的是 0，松手不会触发回弹。
    if (!opts.overScrollTop) next = Math.max(next, 0);
    if (!opts.overScrollBottom) next = Math.min(next, maxScroll.value);

    spring.set(next);
    pushSample(next);
  };

  /** pointerup 和 pointercancel 必须走同一个分支，否则 dragging 会永久为 true */
  const finishDrag = (event: PointerEvent): void => {
    if (event.pointerId !== pointerId) return;
    const element = event.currentTarget;
    if (
      element instanceof HTMLElement &&
      element.hasPointerCapture(event.pointerId)
    ) {
      element.releasePointerCapture(event.pointerId);
    }
    pointerId = null;
    dragging.value = false;

    // 被系统手势 / 多指 / 切 App 打断时不给惯性，否则会莫名其妙甩出去
    const speed = event.type === "pointerup" ? readVelocity() : 0;
    const { projection, minFlingVelocity } = resolveOptions();
    const projected =
      Math.abs(speed) < minFlingVelocity
        ? position.value
        : position.value + speed * projection;
    void animateTo(projected, speed);
  };

  const onPointerUp = (event: PointerEvent): void => finishDrag(event);
  const onPointerCancel = (event: PointerEvent): void => finishDrag(event);

  /* ---------------- 尺寸监听 & 清理 ---------------- */

  let observer: ResizeObserver | null = null;

  watch(
    [viewportRef, contentRef],
    ([viewport, content]) => {
      observer?.disconnect();
      observer = null;
      if (!viewport || !content) return;
      measure();
      // ResizeObserver 是异步批量回调的，别在 pointermove 里读 offsetHeight
      observer = new ResizeObserver(() => measure());
      observer.observe(viewport);
      observer.observe(content);
    },
    { immediate: true, flush: "post" },
  );

  /**
   * 运行时切换越界开关：如果当前 raw 处于「已被关闭的方向」，
   * 用弹簧平滑收回合法区间，而不是瞬间跳变。
   * 拖动中不处理（onPointerMove 会立即钳制，视觉上就是不动了）。
   */
  watch(
    [
      () => resolveOptions().overScrollTop,
      () => resolveOptions().overScrollBottom,
    ],
    ([top, bottom]) => {
      if (dragging.value) return;
      let next = position.value;
      if (!top) next = Math.max(next, 0);
      if (!bottom) next = Math.min(next, maxScroll.value);
      if (next !== position.value) void animateTo(next, 0);
    },
  );

  onScopeDispose(() => {
    observer?.disconnect();
    observer = null;
    unsubscribe();
    // 组件卸载要 cancelAnimationFrame，别让 rAF 在卸载后继续跑
    spring.stop();
  });

  return {
    position,
    velocity,
    maxScroll,
    viewportSize,
    display,
    translateY,
    dragging,
    settling,
    onPointerDown,
    onPointerMove,
    onPointerUp,
    onPointerCancel,
    scrollTo,
    measure,
  };
};
```

这里有个容易被忽略的语义问题：**中断不是 reject**。`stop()` 会把 promise 兑现成一个值（当前落点），而不是抛错,因为对调用方来说"停在 100px"是有效信息，不该变成异常。所以想区分"真的走完了"和"被手势打断了"，就看返回值离目标还有多远。

## 踩坑

// 其中有一些上文已经提到过，此处只是做个小结

**1. `touch-action: none` 是必需品。** 少了它，浏览器会在手势开始的几帧后抢走 touch 事件并抛出 `pointercancel`，表现是"拖到一半突然停住"。加上之后 `pointermove` 才是稳定的。

**2. `pointercancel`必须和 `pointerup`走同一个分支。** 系统手势（下拉通知、边缘返回）、多指、切换 App 都会触发 `pointercancel`。只处理 `pointerup` 会让 `dragging` 永久为 `true`，之后整个组件僵死。

**3. `setPointerCapture` 防止丢事件。** 手指移出元素边界后就不再往这个元素派发 move 了，捕获之后事件会一直送到它身上，松手自动释放。

**4. 只动 `transform`，不动 `top`。** `top` 触发 layout，`transform` 只走 composite。加上 `will-change: transform`，但别滥用，元素多的时候反而吃内存。

**5. 不要在 `pointermove` 里读 `offsetHeight`。** 每帧强制同步布局，60fps 下就是每帧一次 reflow。测量交给 `ResizeObserver`，它是异步批量回调的。

**6. 停止判据要双条件。** 只看速度会在过零点误判。

**7. `requestAnimationFrame` 的时间戳和 `performance.now()` 同一时基，但首帧可能略早。** `Math.max(0, ...)` 兜一下，否则`elapsed`为负，`Math.exp`会给出越来越大的值，动画第一帧直接跳。

**8. 速度必须截断。** 触控板双击、多指、系统时钟抖动都能给出 `20000px/s` 这种离谱值。

**9. 内容高度变化时要把位置收回。** 列表数据变少、窗口 resize，`maxScroll` 变小，`position` 必须被夹回区间，否则下次拖动会先看到一段空白。

**10. 组件卸载要 `cancelAnimationFrame`。** `spring.stop()` 负责这件事，别让 rAF 在卸载后继续跑。

**11. iOS Safari 的边缘返回手势救不了。** 屏幕左缘 20px 的手势由系统接管，页面无法拦截。设计交互时避开这个区域。

**12. `event.currentTarget` 是 `EventTarget | null`。** strict 模式下不能直接 `.setPointerCapture()`，得先 `instanceof HTMLElement` 收窄。同一处还要 `hasPointerCapture` 判一下再 `releasePointerCapture`，否则打断手势时会抛 `NotFoundError`。

## 参数值

| 场景                       | `c`  | `response` | `ζ`       |
| -------------------------- | ---- | ---------- | --------- |
| 长列表越界回弹             | 0.55 | 0.35 ~ 0.5 | 0.6 ~ 0.8 |
| 下拉刷新 / 下拉关闭        | 0.6  | 0.3 ~ 0.4  | 0.8 ~ 1.0 |
| 抽屉 / 半屏卡片            | 0.6  | 0.35       | 0.75      |
| 弹窗进出                   | —    | 0.4        | 0.8       |
| 俏皮的小元件（气泡、角标） | —    | 0.25 ~ 0.3 | 0.5 ~ 0.6 |

调参顺序建议：先定 `response`（快慢），再定 `ζ`（弹不弹），最后微调 `c`（越界的松紧）。

## 什么时候适应这套

- **需要和原生滚动严格同步的场景**（虚拟列表、`position: sticky`、滚动驱动的视差）。自己维护 `position` 就和原生 `scrollTop` 脱钩了，两者对齐的代价很大。这类场景用原生滚动 + `overscroll-behavior`。
- **长距离惯性是核心体验的场景**（相册、信息流）。用本文的"投影 + 弹簧"近似会显得拖沓，需要第五节末尾那套指数衰减 + 边界交接。
- **无障碍要求高的列表**。完全接管 pointer 之后，键盘滚动、读屏器的滚动动作、`scroll-into-view` 全部失效了，需要自己补一套。原生滚动白送这些东西。
- **只想要"禁止越界"**。一行 `overscroll-behavior: contain` 就够了，不要上物理。
